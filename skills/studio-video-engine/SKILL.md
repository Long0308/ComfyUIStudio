## Rules to keep (user rules; ENGINE-PLAN section E wins over any older line below)
No full re-render for a local change: run `jjv plan explain --old --new` first. Preflight (`jjv qa preflight` / `qa gate`) before any render. Music is vocal-free (Demucs gate), library first, SFX off by default, music low and never raised under speech. Brand intro (voice alone -> intro music -> title -> film) is reused, so the film mix has no brand-voice layer unless `episode.audio.brand_voice: film`. Transitions: same seat -> cut + push-in; angle/scene change -> flash/pan; no white frames at seams. Karaoke lights at the audible onset of every word. Icons for opposite words must look opposite. Images are HYBRID (Blender layout -> GPT + local ComfyUI candidates -> compare -> user picks); the engine never holds ChatGPT tokens. A voice take is used only after a human listen approval. No GPU submit without the user's explicit approval for that run. NEWTECONS images are HYBRID since 2026-10-30 (user decision: `comfyui-local` + `codex-exec` + `codex-adopt`, then compare, user picks; OpenRouter stays refused), but NEWTECONS is still unqualified for SeedVR2 until its own pilot receipt.

### Crash recovery and lost prompts (T-E30)
Incident 2026-10-27: ComfyUI aborted (`CUDA error: an illegal instruction`), Docker restarted the container, and the executor waited ~50 min for a prompt that no longer existed (error-db `comfyui-cuda-illegal-instruction-lost-prompt-executor-hang`). Resubmitting without proof stays forbidden; the engine now supplies the proof.

**LOST** = ALL of: (1) the container is a DIFFERENT instance than at dispatch: just before the POST, `dispatch` writes the container's `StartedAt` text (`docker inspect`, injectable `ContainerProbe`) into the dispatch intent as `container_instance`; the proof compares the CURRENT `StartedAt` text with that recorded value and requires them to DIFFER. The two values are only ever compared with each other: the host clock is never compared with the Docker VM clock (clock skew can not fake or hide a restart). No recorded value (an intent written before this version) = `UNCERTAIN`. A dispatch whose `StartedAt` can not be read is REFUSED before the intent is written (`Uncertain`, stage `container_instance_unavailable`, nothing sent): a prompt that can never be proven lost can only hang; (2) the prompt is absent from `/history` and `/queue` in TWO consecutive checks `lost_recheck_seconds` apart (no prompt id on file: the intent's exact graph sha + client_id stand in); (3) no output file with the chunk prefix in the ComfyUI output folder. `NOT_LOST` if the `StartedAt` is unchanged, the prompt appears, or any output exists; `UNCERTAIN` if docker, ComfyUI or the output folder can not be read, the container is not running, or no `StartedAt` was recorded at dispatch. The output ROOT (`comfy.output_dir`) must exist and be a readable directory, and only `FileNotFoundError` on the prefix sub-folder counts as absence: a missing, non-directory or access-denied root or prefix folder (unmounted drive, wrong path, ACL) is `UNCERTAIN`, never "no output" (`Path.is_dir()` swallows `PermissionError`, so `os.stat` is used). Only LOST can lead to a re-dispatch; everything else keeps the old stop (exit 2, or 3 on the hard timeout) with the verdict in `failure.evidence.lost_classification`. **UNCERTAIN stops the run:** the stall watchdog counts consecutive stalled windows whose proof is UNCERTAIN; after 3 (`MAX_CONSECUTIVE_UNCERTAIN`, a code constant, no config key) it writes `runs/<shot>/<chunk>/INCIDENT-stall-uncertain.json`, raises stage `stall_uncertain` (exit 2, no POST) instead of waiting out `history_timeout_seconds`; only a NOT_LOST or LOST verdict resets the count (progress between stalled windows does not; conservative by design).

On LOST (`engine/comfy/lost.py`, `engine/seedvr2/recovery.py`): the chunk folder's state (job, intent, submitted, history, telemetry, output/, core/) moves to `runs/<shot>/<chunk>/abandoned-lost-<ts>/` with `LOST.json` (evidence: container `StartedAt` before/after, dispatch time, both history/queue snapshots, outputs checked, GPU fault signature = CUDA error / Fatal Python error / OOM lines from `docker logs --since <dispatch>`) and `INCIDENT.json` (archived files with sha256). Log lines are REDACTED before they are stored (`Bearer/Basic/Digest ...`, `sk-...`/`ghp_...`/JWT shapes, `key=value`, `key: value`, `"key": "value"` and `'key': 'value'` for api_key/token/password/secret/authorization incl. quoted values with spaces, URL userinfo `scheme://user:pass@`, and any 32+ character hex/base64-like word that is not a file name or path) and capped at 400 characters; the fault text, file names and paths (anything with a dot, a separator or a drive letter) stay readable. The chunk is then dispatched afresh (a normal guarded dispatch: idle queue, lock, new intent, new `container_instance`); the new `job.json` carries `lost_redispatches`. **Retry budget:** every archive appends one row to the append-only `runs/LOST-LEDGER.jsonl` (written right after the archive folder is created, before anything moves); a chunk's used retries = `max(ledger rows, abandoned-lost-* folders)`, so the limit survives an executor restart AND the deletion of an archive folder. A ledger that records MORE archives than exist on disk means evidence was removed: stage `lost_ledger_mismatch`, exit 2, no POST (restore the folder, or investigate and hand-edit the ledger yourself; the engine never edits it). The check runs only where a chunk is about to be dispatched or re-dispatched (not for a COMPLETED chunk), so `--resume` can still verify finished chunks. Retries used up: `LOST-retries-exhausted.json`, stage `lost_retries_exhausted`, exit 2, no POST. The same proof runs on `--resume` when an intent's prompt is gone (the incident replay: kill the hung executor, `--resume`), and at the hard timeout before `WaitTimeout`. `run-state.json` `lost_redispatches` lists every re-dispatch of the plan across executor restarts (earlier entries are loaded at start and appended to).

**Stall watchdog** (`engine/comfy/watchdog.py`): after each empty history poll it fingerprints progress (queue prompt ids, output files with the prefix and their sizes, a 256 MiB GPU-memory bucket when telemetry runs). Quiet for `stall_factor x expected_chunk_seconds` -> the LOST classification runs again: LOST -> as above; otherwise a stall alert is appended to `runs/<shot>/<chunk>/stall-alerts.json` (also `job.stall_alerts` and stderr `STALL ...`), the watchdog re-arms, and the wait continues until `history_timeout_seconds`. Expected seconds = `machine.resilience.expected_chunk_seconds`, else the plan's per-chunk `estimate.gpu_seconds_linear_by_padded_frames`, else 600.

**Single-executor guards** (`engine/core/runlock.py`): `execute --execute` takes TWO visible PID locks (O_EXCL; pid, process start time, host, plan, token), then the OS run lock: (a) the plan lock `runs/RUN-LOCK.json`; (b) the MACHINE lock `EXECUTOR-RUN-LOCK.json` in the folder of `machine.gpu_lock_path` (no new config key: derived from the existing one), held for the whole run, which excludes an executor of ANY OTHER plan on this machine. A live holder (same host, pid alive, same start time) -> `Refused` naming the holder (pid, host, plan), never broken, not even with the flag. Dead pid or a reused pid -> reported as STALE; re-run with `--break-stale-lock` (applies to both locks; writes `runs/stale-lock-[machine-]<ts>-<pid>.json`, then takes over). Breaking is race-safe: breakers are serialised by a `<lock>.break` guard file (a second breaker waits up to 5 s, then refuses naming the guard; delete a leftover guard by hand only when no executor is starting), the lock is re-read IN PLACE (never moved, so a live lock is never absent) and removed only if it still carries the token that was judged; if another executor replaced it meanwhile the break is refused and nothing is touched. OS errors on the lock rename/unlink paths become `Refused` (a Windows sharing violation is retried for ~0.5 s first); writing the stale-lock report into an unwritable folder can still raise (see Known limits below; the lock is not removed in that case). Another host or an unreadable lock is never broken. Dry run takes no lock.

**Known limits (documented, not fixed):** (i) deleting `runs/LOST-LEDGER.jsonl` AND every `abandoned-lost-*` folder of a chunk resets its retry budget (the engine can not tell a clean slate from a tampered one); (ii) the container identity is the `StartedAt` TEXT docker prints: a change of its formatting for the SAME instance would read as a restart, but LOST still also needs absence from `/history` and `/queue` twice and no output file; (iii) a prefix sub-folder deleted under a readable output root reads as absence by design; (iv) a stale `.break` guard or a leftover `*.aside` from an older run is clutter that blocks only lock BREAKING, never a normal start.

**Operator rule (the engine can NOT enforce this):** a non-engine executor, such as the frozen ep04 v004 script `tools/execute_seedvr2_production_v004.py`, does not take the machine lock. NEVER start an engine `execute --execute` while a non-engine executor is alive: check its PID file / `Get-Process -Id <pid>` first (the ComfyUI queue-idle guard and the GPU submit lock only protect the POST instant, not the run). Before relaunching any executor: confirm the old PID is gone and the log folder exists.

Config (optional `resilience` object in the machine config, schema `machine.schema.json`; ABSENT in `production-local/engine/machine.json` on purpose, because plans hash the whole machine config; code defaults apply). The machine lock and the UNCERTAIN-stall limit (3) need no key:
| Key | Default | Meaning |
|---|---|---|
| `max_lost_retries` | 1 (0-5) | automatic re-dispatches per chunk after a proven loss |
| `stall_factor` | 3.0 (>= 1) | stall window = factor x expected chunk seconds |
| `lost_recheck_seconds` | 5.0 | gap between the two absence checks |
| `expected_chunk_seconds` | none | override of the plan's per-chunk estimate |

### QA: `jjv qa av` (T-E28a)
`jjv qa av --episode E --video V.mp4 --config review-config.json [--reference R.mp4 [--reference-seconds N]] [--out receipt.json] [--allow-outside PATH]... [--json]`.
Decodes the export (ffmpeg, mono 48 kHz) and cross-correlates (FFT NCC, numpy) every WAV bound in the config around its start frame; reports the lag in ms and fails if `|lag| > tolerance` or `ncc < ncc_min`. Config sources: `wav_bindings[]` (engine config, authoritative) or, only for a hand-built config, `dialogue[].audio` + `outro_cards[].audio`. A PRESENT `wav_bindings` key must be a non-empty list (null, `[]` or a non-list is `Refused`, never a silent fall back); an engine-built config (it carries the `jjv/review-config/` schema string, `inputs.boundaries_sha256`, or engine-shaped dialogue rows (a `timing_audio` key; hand-built rows lack it), so deleting one marker does not disguise it) REQUIRES `wav_bindings`, absent is `Refused`, because the hand-built fallback would verify only the 12 outro-card rows and still PASS. The receipt records `binding_source` (`wav_bindings` or `hand_built`) and `binding_count`, and the stderr table prints them. When BOTH are present they are not unioned: every hand-built row must be one of the `wav_bindings` (same path compared normalised, so `./audio/a.wav` equals `audio/a.wav`; same sha256 and start frame; the engine config carries its card WAVs in both places), otherwise `Refused`; a malformed hand-built row (missing `id`/`term`/`start_frame`/`path`, a non-object row or a non-list block) is `Refused` too, and so is a PRESENT `audio` key that is not an object: `""`, `0`, `[]`, `false`, `null` are never skipped as "no audio" (a blanked row would drop its WAV from the verification and still PASS); a row without audio omits the key, because a WAV declared only in the hand-built block would be silently skipped and a disagreeing copy would hide which start is real.
- **No fail-open binding:** a binding without a sha256 is `Refused`; the WAV on disk must hash to it (receipt-WAV rule).
- **Thresholds:** defaults: tolerance half a delivery frame (500/fps ms, 16.7 ms at 30 fps), `ncc_min` 0.3, `search_s` 0.5, `pcm_max_abs` 1e-3, `slack_samples` 2048, `silent_peak_max` 1e-3. `config.qa.av` may only TIGHTEN them, else `Refused`: `tolerance_ms`, `silent_peak_max`, `pcm_max_abs`, `slack_samples` at most the default; `ncc_min` at least the default; `search_s` within `[0.1, 0.5]` (a smaller window cannot expose a late WAV); `reference_seconds` > 0 and not shorter than the reference floor (see `--reference` below). Every value must be a finite non-negative number (bools refused). A config cannot declare its own PASS: `tolerance_ms: 1e9`, `ncc_min: 0`, `silent_peak_max: 0.9`, `search_s: 0.01` are refused. A correlation peak on a real edge of the search window is status `edge-hit` and FAILs (the best match may lie outside the window). The receipt records where each value came from.
- **Silent WAVs** (peak below `silent_peak_max`) cannot be located by correlation. A binding must then carry an `expect_silent` window (`build-config` writes it from `boundaries.json`); the EXPORT RMS in that window is measured, reported (`expect_silent.export_rms`) and must not exceed `max_rms`. Such a row has `placement_proven: false`, is listed in `unverifiable_silent_wavs` and `caveats`; a silent WAV without a window, `expect_silent` on an audible WAV, or a binding whose `start_frame` differs from the window's `start_frame` (`silent-misplaced`) fails.
- **Input validation (exit 1, never a traceback):** every binding needs `name`, `path`, `sha256` and an integer `start_frame` (a float such as 240.9 is `Refused`, not truncated; same for hand-built `start_frame`/`offset_frames`, which default to 0 only when ABSENT: a present `0.0`, `false` or `null` is `Refused`); `expect_silent` is validated against `silent_bound` of `schemas/boundaries.schema.json` (`start_frame`, `end_frame_exclusive`, `max_rms` finite, no other key, non-empty window).
- **`max_rms` is bounded:** `0 < max_rms <= 0.05` (`SILENT_MAX_RMS_CEILING` in `engine/qa/bindings.py`, same number as the schema `maximum`; a test pins the parity). Measured on ep04: the quietest dialogue WAV has RMS 0.0731, the S06_B3 bed 0.0279. Choose bed-relative (`measured bed x sqrt(2)`, a source as loud as the bed raises the window 3 dB), never above the ceiling; record the measurement next to the boundaries file (ep04: `engine/boundaries.README.md`, `max_rms` 0.04).
- **Scope:** every file (video, reference, WAVs) must be inside the episode root unless named by `--allow-outside`; receipts echo episode-relative paths (file name only if outside) plus sha256, never absolute paths.
- `--reference` compares sample-by-sample (minus the AAC slack). The floor of the window is derived independently of the config being checked: the episode's main film (`rules.timeline_frames` of the episode config, passed by the CLI; ep04 now 3384 f = 112.8 s, from `jjv config contract --episode 04-milk-and-mom` on 2026-10-28; the whole master with the end card is 3444 f = 114.8 s; the earlier "84 s of an 86 s export" was pre-3444 and is historical, the export itself was not re-probed) or, for a library caller that passes none, the whole overlap `min(len(export), len(reference))`; a field of the review config (e.g. its own `main_frames`) is never trusted for it. Window: with no value the WHOLE overlap is compared (`window_source: full overlap`); `config.qa.av.reference_seconds` (`config`) shorter than the floor is `Refused` (a prefix would hide a later divergence; build-config writes `timeline.main_frames / fps` (`engine/editorial/build.py:129`; ep04 now 3384 / 30 = 112.8 s, equal to the floor; derived from the code and the contract, build-config was not re-run)); an explicit `--reference-seconds N` (finite, > 0, else `Refused`; `cli`) is used as given, but when it is shorter than the floor the receipt has `partial: true` and a clean comparison is verdict **`PASS_PARTIAL`** with `ok: false` and exit 1, never `PASS` (chosen over a new exit code so anything that only checks `ok` or the exit status fails closed; automation that wants the nuance reads `verdict`/`partial`). There is no margin below the floor: the comparison itself drops the last `slack_samples` (encoder padding) ONCE, so even a window exactly at the floor compares `floor - slack` samples; a second margin would hide twice the slack.
- Receipt `config_sha256` is the sha256 of the review-config FILE that was checked. (The `config_sha256` printed by `jjv config validate`, e.g. in the tails-plan evidence, is a different thing: a hash embedded in the resolved machine/domain/recipe/episode configuration, not the hash of any one file.)
- Exit 0 PASS, 1 FAIL / PASS_PARTIAL or rule violation (`Refused`: bad binding, threshold or window, never a traceback), 2 missing/unreadable input (`Uncertain`: video, WAV, config, episode, ffmpeg, or a JSON document that is malformed or holds `NaN`/`Infinity`). Strict JSON (`NaN`/`Infinity` rejected) is enforced by `core.io.read_json`, which the engine's own documents use, including `engine/config/pins.py`; the nine remaining direct `json.loads` sites are NOT routed through it and still accept those constants: ComfyUI HTTP/graph/history parsing (`engine/comfy/client.py`, `commands.py`, `lost.py`), `core/runlock.py`, `frozen.py`, ffprobe output (`media/probe.py`), the recipe graph (`seedvr2/recipe.py`) and the voice client's HTTP parsing (`engine/voice/client.py`, two sites, owned by another builder and not edited here). The receipt has no timestamp; `--out` is write-once. Code: `engine/qa/{av,bindings,cli,scope}.py`.

### Editorial: `jjv editorial build-config` (T-E28a)
`jjv editorial build-config --episode E --boundaries boundaries.json --word-timing WORD-TIMING.json --out DIR [--dry-run] [--allow-outside PATH]...` writes `DIR/review-config.json` and `DIR/events.json` (write-once, deterministic, no timestamps; `--dry-run` validates everything and prints hashes). `boundaries.json` (`schemas/boundaries.schema.json`, paths relative to the episode root) declares one row per boundary `{frame, from_shot, to_shot, class carry|cut, type, frames, direction, motivation, continuity agree|mismatch|unknown, g_bridge?, tail_clip?, params?}` plus `icons` (declared term list + style), `cards` (outro cards + WAVs), `expect_silent` (one window per silent shot; a second row for the same shot is `Refused`) and `ending` render parameters. Canonical type vocabulary (snake_case): `none whip dip_white cloud bubble dissolve wipe iris bloom card_slide plate_in`. Every transition record carries `shows_both`; it is true for `dissolve cloud bubble wipe card_slide plate_in`.
Rules. Rule violations are `Refused` (exit 1, nothing written); a missing or unreadable input (file, clip, WAV, icon, episode, or a JSON document that is malformed or contains `NaN`/`Infinity`) is `Uncertain` (exit 2):
- a `shows_both` type is forbidden when a picture shot is on either side unless continuity is `agree`; between two graphics (cards, plates) it is allowed;
- tail-only types and the `dip_white` outgoing frames need `ceil(0.8 N)` native tail frames beyond the editorial cut (the `tail_clip` is probed with `engine/media/probe.py`), and the last native index used must exist;
- every hard cut has a designed type, a carry has none, `frames == 0` iff `none`, every row has a motivation, whip/bloom frames are even, whip/card_slide have a direction;
- coverage and position: every shot pair, intro->first, last->outro and card pair has a row; the frame equals the incoming start; the class agrees with `shots.json` `entry.kind`;
- captions: every dialogue entry has word timing that spells its script, is monotonic, starts AND ends inside its window, and uses method `whisper-*` or `estimated` (estimated is marked on its icon events); windows tile the timeline;
- audio binding: shots.json WAVs hash to their receipt; a one-shot dialogue's timing `audio.sha256` is REQUIRED and equals its WAV; a multi-segment dialogue's timing WAV must hash to its declared sha and be sample-identical to the concatenation of the bound segment WAVs; a silent WAV needs an `expect_silent` window equal to its shot's window and no word timed inside it, an audible WAV needs at least one word in its window;
- WAV offset, one source of truth: `shots.json` `wav_binding.offset_s` (the receipt-bound one, it places the WAV binding). `offset_s x fps` must be a whole number of frames (within 1e-6), else `Refused` (a sub-frame remainder would be rounded away silently). The word timing's `audio.offset_frames` (default 0) must equal it for the entry's first shot, otherwise `Refused` (a timing-only or shots-only offset would move icons away from the audio); the icon pop uses the shots.json value. A NON-FIRST segment of a multi-segment dialogue may not have a nonzero `offset_s` (`Refused`): the word timing carries one offset per dialogue, so captions and icons cannot follow a later segment's WAV. A silent shot may not have a nonzero offset (its binding must start at its `expect_silent` window);
- icons: events from anchor words; raw whisper start wins when it differs from the calibrated start by more than 0.3 s; the (agreed) WAV offset is added; every declared term must be covered; the timing file's own list may not drift;
- end plate: its start must equal `ceil` of the measured end of the last card's speech; WAVs/logo/clips must hash to the declared sha256; every referenced file must be inside the episode root (or allow-listed).

### Word timing: `jjv timing words`, `jjv qa words` (T-E33)

`jjv timing words --episode E --dialogue F --out DIR` (CPU only) runs recognition, applies the onset rule to every word (a port of the verified ep04 v003/v004 hand tools), then the Q1 gate. Recognition runs in the machine's Python (`machine.timing.python` / `--python`) with the model from `machine.timing.model_dir` / `--model`; a missing interpreter, model or package is `Uncertain` (exit 2). Until the `machine.timing` keys land (audit gap 7), pass `--python` and `--model`. Outputs, write-once: `WORD-TIMING.json`, `WORD-TIMING-QA.json`, `timing-receipt.json`. Recipe selection: `--recipe` > episode.timing.recipe > the domain default_for_domain recipe (or its sole recipe). The selected id must match domain.timing.allowed_recipes exactly; missing or malformed allow-list refuses, and [] authorises no recipe. No fallback to another allowed id. The loaded recipe must belong to the episode domain. NEWTECONS timing.allowed_recipes is now ["timing/ntc-vi-words-v001"] (domain file, 2026-10-31), so only that recipe id is authorised for NEWTECONS timing. Schema now supports domain.timing.allowed_recipes (unique timing/<name> ids).

`jjv qa words --episode E --timing F [--out R]` is the independent Q1 detector. It FAILs unless its built-in negative control is flagged (a passing word shifted 5 f early, and one shifted 2 f early). Exit codes: 0 PASS; 1 Q1 FAIL or rule violation; 2 missing input, recognition not configured, an unheard script word, or UNTESTABLE.

Rules of the onset pass (every word; a port of the hand-run v003/v004 tools): the line-first word = first sustained speech run (a breath/click burst is skipped); a word that starts in silence moves to the rising edge of the first sustained voiced run (rule A); a word that starts on sound but has a pause just before its sound moves to the edge after the pause (rule B, shift capped 0.60 s); never earlier, never later than end - 2 f; a stop closure inside a word ("liquid") does not move it. A script word that was not heard is `Uncertain` (no estimated time). `--recognised WORD-TIMING.json` skips recognition and re-applies the rules. Recipes: the historical cartoon default `timing/words-onset-v003` and explicit v001/v002 selections via `--recipe` are subject to exact membership in domain.timing.allowed_recipes and recipe-domain matching; an explicit selection does not bypass either gate. v003 = early > 1 f FAIL, late 1-2 f PASS, 3-6 f `WARN-late` (listed in `summary.warn_words`, does not block), > 6 f FAIL, onset at -42 dBFS voiced edge; both negative controls (5 f and 2 f early) must be flagged else the gate FAILs; no word after a pause = `UNTESTABLE` (exit 2). Every WAV is hash-bound to its declared sha256 (`Refused` on mismatch; outside the episode root needs `--allow-outside`). Outputs (write-once, no timestamp): `WORD-TIMING.json`, `WORD-TIMING-QA.json`, `timing-receipt.json`. Parity: the engine reproduces the hand-run ep04 v004 timing (108/108 words, 0 differences, fixture test). Full pipeline, recipe history and tests: [references/stages.md](references/stages.md) (section Word timing).
