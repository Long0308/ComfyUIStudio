## remotion-kit (T-E28b): one compositor for review cuts and the 4K master

(Replacement text for the section of the same name in `studio-video-engine/SKILL.md`; root merges it. `SKILL-SECTION-r4.md` .. `-r9.md` are
superseded and deleted. The one-line pointer in the "Editorial" section stays: the review render is this section.)

`remotion-kit/` is the shared, config-driven Remotion package: the review cut (scale 1, labelled) and the master (scale 2, no label) of every JennieJoy episode render from the same components, no per-episode fork. CPU only (SwiftShader, `--concurrency` 1 or 2), no GPU/ComfyUI. Full documentation: `remotion-kit/README.md`.

| Item | Content |
|---|---|
| Entry | `node remotion-kit/render.cjs --config kit-config.json --browser <cached headless shell> [--mode review\|master] [--stills ...\|--still N --out F\|--range A-B (--out F\|--png-seq D)\|--out film.mp4] [--check-only]` (browser: `--browser` or `REMOTION_BROWSER`; the kit never searches episode folders or downloads one) |
| Composition | `Film({config, scale, label, previewMark, sources})` + standalone `EndLogo`; size and length come from the config and `scale` (1920x1080 design canvas). |
| Config | schema `jjk-remotion-kit/config/v1`: `timeline`, `shots[]` (word timing, segments, `captionLines`, optional `speechOnsetF` + `onsetEvidence`), `transitions[]` (canonical types, the same table and `shows_both` / `tail_only` as `engine/editorial/transitions.py` `TYPE_PROPERTIES`, asserted by a test that parses that file: `none whip dip_white cloud bubble dissolve wipe iris bloom card_slide plate_in`; a tail is `{startFrom, editorialFrames, fileFrames, verifiedFrames}`, all required), `icons[]`, `ending`, `cards[]`, `strings`, `intro`, optional `clock.shotTable`, `theme`/`motion` preset overrides, optional `waivers`, and render-time `bindings` (`{path, sha256}`; a final master source also `receipt: {kind, path, sha256, binds, transition?}`; a PREVIEW source may carry `materialized`, a final may not; never passed to the compositor). Presets: `src/presets.mjs`. |
| Tail numbers / build binding | `startFrom`, `editorialFrames`, `fileFrames` and `verifiedFrames` come from the build's events record (receipt-bound): `events.transitions[id].outgoing_tail` (`start_from_frame`, `editorial_frames`, `native_frames`, `tail_output_frames`). The events file is a BUILD artifact (the build script computes these numbers itself; it is not trusted engine output) and config + events can be edited consistently, so the build is bound to its receipt: `loadBuild()` reads the config, the events file and the receipt once each and refuses unless the sha256 of the config and of the events file equal the ones in the build's `RECEIPT.json` (for an engine-built build: the hashes the REAL stdout of `jjv editorial build-config` nests under `outputs["review-config.json"]` / `outputs["events.json"]`, `ok` true; tested with a summary produced by actually running the engine into a scratch dir) and the word timing is bound too: a build receipt MUST carry `word_timing.sha256` (a receipt without it is refused) equal to the config's `word_timing.sha256`, and the engine summary has no word-timing key, so there the word-timing document itself (path resolved against `episodeRoot`, required for a relative path) is hashed and compared with the config's `word_timing.sha256`. `adapt()` refuses a build not loaded that way: the token `loadBuild()` returns is frozen and registered in a module-private set, so a hand-built or copied token is refused (unforgeable). The receipt sha256 is recorded in `provenance.build_receipt`, and the provenance hashes of the config and events are those of the verified bytes, not a re-read. On top of that the adapters refuse a config whose own copy of the tail differs by one frame from the events record, a tail in only one of the two files, and any master `tail_output_frames` / `editorial_frames` / `native_frames` / `review_start_from_frame` that differs. The value is build-dependent (3 for the earliest dip schedule, 1 for the later 8-row one), so tests compare with the events file, never with a constant. A transition may play at most `verifiedFrames` tail frames (the engine's `check_tail` is monotone in N: fewer is covered by it). |
| Review vs master | same config; master = `--mode master`, scale 2, crf 16, no label (a label is refused), 4K bindings and 4K tail start frames from the master config. Review needs `config.review.label` (G-LABEL). |
| Refusals (config, at `--check-only` / mount) | a `shows_both` type with a picture shot on either side (a shot id, or ANY segment id of a shot) and no `continuity:'agree'` (between two graphics it is allowed); tail-only types (`dissolve cloud bubble wipe`) without an outgoing tail, or whose `from` is not a real shot / last segment ending at the boundary; transitions not anchored to their shots (integer `start`, `boundary` = incoming start and outgoing end, tail-only `start === boundary` = incoming start); `from` / `to` that name no shot, segment or graphic; more than one incoming or outgoing transition on an edge segment; engine row rules (even whip / bloom frames, `dip_white` frames == schedule length, `none` <=> 0 frames, direction for `cloud wipe card_slide`); any frame with two shot pictures unless every tail belongs to a `continuity:'agree'` transition (per-frame audit); dip schedule errors (one white peak, `out` only at t<0, `out_tail` / `in` only at t>=0, `out_tail` rows contiguous t=0..n-1 and needing a tail); a transition that plays more tail frames than `tail.verifiedFrames`; a dip white peak on or after the incoming shot's first SPOKEN frame (`dip_peak_before_first_word`) or whose sparkle burst (peak +- `motion.dip.peakSpan`, while `motion.dip.sparkles > 0`) reaches it (`dip_sparkle_before_first_word`); a whip extender strip that does not cover the exposed side for every offset of its schedule (`whipCoverage`); logo disc covering the first vocab pill or still sliding after its word starts; end plate before `speechEndFrame`, before the last word, or without an end card; `tail.editorialFrames` / `fileFrames` / `verifiedFrames` missing; non-canonical type names. |
| First spoken frame | from the word-timing onset evidence when the config carries it (`shot.speechOnsetF`: the first sustained / voiced onset measured on the bound WAV, e.g. word-timing `onset_fix.new_start_frame`), because the caption start can sit on the unvoiced 2-5 frame pre-roll of the WAV (noise, not speech); otherwise the caption start, and then every message and the rule report say "caption-based". The first episode's review adapter reads the evidence from the word-timing file the build names and REFUSES a build with no `word_timing` reference, a missing file, or no recorded sha256 (a word timing without onset data is the only "caption-based" case). |
| Refusals (render / staging) | a bound tail file that does not satisfy the engine `check_tail` rule exactly (`available = frames - editorialFrames >= ceil(4N/5)`, `ceil((startFrom+N-1)*nativeFps/fps) <= frames-1`; tested against the real engine on a 33,120-case grid, nine fps pairs, plus a dip_white grid) or whose frame count differs from `tail.fileFrames`; a bound final picture clip shorter than its window; in master mode a final source without a receipt binding, with a changed receipt, or whose receipt CONTENT does not attest the clip (staging re-reads it with the same module the adapter uses, in ONE read: the content check and the recorded hash come from the same bytes); a FINAL source carrying `materialized` (finals stage exactly the attested bytes and the staged file is re-hashed against the attested sha256); `--preview` outside stills / a `--range` that does not cover the whole film, in any mode; `--no-preview-mark` (removed); `--drop-preview-mark` outside `--reproduction-only DIR` stills; concurrency > 2; master with a label; any waiver in a master-mode render other than stills; a reproduction-only waiver without `--reproduction-only DIR` (all outputs inside DIR). |
| Waivers / marks | the only way a historical config passes a waivable rule (`dip_peak_before_first_word`, `dip_sparkle_before_first_word`): `waivers[]` of `{rule, transition, reason, review_render_sha256}` plus EITHER `approved_by` + `approved_at` (a real calendar date) OR `reproduction_only: true` (no approval fields, not an approval; the render needs `--reproduction-only DIR`). A waiver without its fields does not waive, an unneeded waiver is refused, every used waiver is printed (`WAIVED ...`) and copied into the render record. Adapters create waivers only from an explicit option and never invent approval fields. A waiver never removes the PREVIEW mark: master stills are unmarked by design ONLY when they come from preview sources through `--reproduction-only DIR --drop-preview-mark` (parity runs, outputs inside the parity work dir, record stamped `reproduction_only`); every other preview still or range carries the mark. |
| Engine schedule (recorded, not "fixed") | the engine still encodes the 9-row / 3-tail-frame dip schedule (`transitions.py` `DIP_WHITE_SCHEDULE`, "the dip-to-white schedule is 9 frames"); review builds v009..v012 use a later 8-row schedule with `tail_output_frames` 1, which the current engine refuses. There is NO approval artifact for that design (v010 is not user-approved; v012 is under review). The rule report (`episodes/ep04/parity/PARITY.md`, column "engine dip schedule") shows them as "engine-schedule mismatch (later design, BRIEF v009; not engine-verified)" for T1010, T1310, T1610. The films are not changed and the engine side is updated separately. |
| Rule report per build (adapted without waivers; every build receipt-bound) | the earliest build (v008): 3 dip-peak issues (T1010, T1310, T1610), first spoken frame caption-based; v009 and v010: 3 sparkle-reach issues each (T1010, T1310, T1610: the peak is one frame before the first word but the sparkle burst, peak +- 1, reaches it; caption-based first frame because their word timing has no onset evidence); v011 and v012: 0 issues (onset evidence). |
| Episode adapter | an episode supplies a kit config (any tool). `remotion-kit/episodes/ep04/` holds the first episode's adapters (review build, accepting the engine-built `events.json`; master variant, which refuses unless `master_ready`, nothing is missing, the master supplies exactly the kit's picture and tail keys, the same clock and a receipt for every final source, refuses a config without `native_restored_fps` (no default), and derives each tail's numbers from the events record and the master `tail_source`, refusing inconsistent values) and `run_parity.py`; episode numbers live only there (`remotion-kit/tests` greps the kit for them, including frame and `T<nnnn>` literals). `adaptMaster()` checks structure, clock and receipts; the media probes run in the adapter CLI and in staging. |
| Tests / parity | `npm test` in `remotion-kit` (`node --test "tests/*.test.mjs"`: literal grep, validation, per-frame audit, tail files vs the engine, label / waiver / preview / reproduction gates, adapters, receipt content, materialized finals, events-record binding, the dip rules per real build). Parity: `python -I remotion-kit/episodes/ep04/run_parity.py --work <scratch> --report-dir <scratch with the committed pins copied in>` (RGBA md5 against the original compositor's lossless frames and the existing master stills; property checks, the rule report and the no-reference change detectors are listed separately and are not parity; a missing pin file fails unless `--pin`; renders run with `--reproduction-only <work dir>`). |
