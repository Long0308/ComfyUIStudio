## T-E42 (kit side): effects are presets, validation and renderers read the catalog

For the root to merge into SKILL.md (not edited here). Principle (one paragraph): a transition effect is a COMPOSITING layer over shot videos that
already exist. Changing the effect re-composites; it never asks for shot video (no H3, no SeedVR2, no GPU). A preset that plays the outgoing tail
(`tail_frames` all / half / schedule) is available only where the tail handle exists; otherwise it is refused with the missing frames named and no
GPU work is requested.

### Catalog sync

- Source of truth: `<skill>/schemas/transition-presets.json` (`jjv/transition-presets/v1`), generated by `gen_presets.py`. Never hand-edit it, in the
  kit or anywhere.
- `node remotion-kit/tools/sync-catalog.mjs` writes `remotion-kit/src/catalog.generated.mjs` (rules only: the display keys `label`, `when`,
  `kids_note` stay in the JSON for the gallery / CLI; the file records the catalog's sha256).
- `node remotion-kit/tools/sync-catalog.mjs --check` exits 1 on drift (`--catalog FILE` / `--out FILE` exist for tests). `npm test` runs it.
- `TYPE_TABLE`, `TRANSITION_TYPES` and `NEEDS_CONTINUITY` (`picture-mode.mjs`) are derived. Every READY preset is a valid kit `type`; planned ones are
  refused ("preset 'glitch' is planned, not implemented ..."). The old F10 test (python source text) is replaced by `tests/catalog-sync.test.mjs`,
  which also loads the engine's own `engine/editorial/presets.py` (`tests/engine_presets_probe.py`) and compares shows_both / tail_only / frames /
  params / schedule / tail frames / window for every ready preset.

### Validation (`validate.mjs`, rules from `presets.mjs`)

frames (fixed / min..max / even; a dip row's own schedule wins and must equal its length), direction (required means +1 / -1), params (unknown refused,
type / min / max / enum), tail window from `tail_frames` (none / all / half / schedule) shared by `tailWindow()`, staging, `tail.verifiedFrames` and the
audit, window mode (`start` / `end_exclusive` must be where at_boundary / centred / from_boundary / schedule / iris puts them), continuity `agree` for
`shows_both` presets between pictures, `safe_for`, dip-family rules (one pure frame, `out` before / `out_tail` and `in` after the boundary, contiguous
tail rows, peak and sparkle burst before the first spoken word; `params.sparkles: false` means reach 0), `preset` / `renders_as` / `shows_both` on a
row must agree with the catalog. `collectWarnings(config)` returns warnings that are never refusals (same_framing + a visible transition, legacy
9-frame dip). Existing v008 configs (`type: dip_white`, 9 frames) resolve to `dip_white_legacy` and keep validating.

### Renderers (fixed-timeline overlay model, descriptors in `src/catalog-render.mjs`)

- `cut_push`: only the incoming picture, settles from `scale_from` to 1.
- `push_slide`: out and in travel one canvas apart along `axis`; `direction` +1 = out leaves left; `ease`.
- `zoom_through`: out scales to `scale_out` and fades with blur, in grows from `scale_in_from`. `zoom_out`: out shrinks to `scale_to` above the incoming and fades at the end.
- `iris_circle` / `iris_diamond`: the incoming picture is revealed through a growing circle / diamond at (`centre_x`, `centre_y`).
- `clock_wipe`: incoming revealed through the swept sector (centre, start-ray point, corners passed, end-ray point).
- `blinds`: `count` slats along `axis`, each opening by the same fraction.
- `blur_crossfade` / `focus_pull`: opacity plus blur on out / in (focus_pull defocuses only the outgoing picture).
- `crossfade` / `dissolve`, `wipe_linear` / `wipe` / `cloud` / `bubble`, `whip` / `pan_motivated`: the existing renderers (aliases share a `renders_as`).
- dip family (`dip_white`, `dip_white_legacy`, `dip_black`, `light_leak`, `film_burn`): schedule weight -> exposure, blur and an overlay (flat colour,
  or seeded radial leak / burn blobs over a base that is opaque on the pure frame).
- `card_flip_3d`: one face per frame: out rotates 0 -> 90 over `ceil(frames/2)` tail frames, then in rotates -90 -> 0 (`axis`, `perspective_px`).

Every descriptor is pure (no clock, no random source), is applied by the generic layers (`LayerFx`, `DipOverlay`) to the outgoing tail layer and the
incoming shot picture, and is audited by `auditSeries` (outgoing whole on the first frame, incoming whole on the last, no frame with both pictures for
a one-shot preset, at least one for a both-sides preset, coverage monotonic). `validateConfig` runs that audit on every descriptor transition.
