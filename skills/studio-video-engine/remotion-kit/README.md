# remotion-kit

One config-driven Remotion code base for the JennieJoy episode compositor. The **review cut** (1080p, labelled) and the **4K master**
(2160p, no label) of every episode render from the same components and the same kit config. There is no per-episode fork of
`caption.jsx`, `transitions.jsx`, ... any more: an episode supplies a config, nothing else.

Domain: `jenniejoy_cartoon_3d` only. CPU only (Remotion + SwiftShader, `--concurrency` 1 or 2), no GPU, no ComfyUI.

```
remotion-kit/
  render.cjs              renderer: stills, --range, PNG sequence, full film (review or master)
  src/
    index.jsx             registers compositions `Film` and `EndLogo`; size/length come from calculateMetadata
    film.jsx              Film({config, scale, label, sources}), ScaledCanvas, ReviewLabel, EndLogo
    context.jsx           KitProvider / useKit (resolved theme + motion presets), card timeline helper
    presets.mjs           DEFAULT_THEME, DEFAULT_MOTION (all presets), deepMerge, easings, the preset-catalog rules (frames / direction / params / tail / window)
    catalog.generated.mjs the transition-preset catalog as data (GENERATED by tools/sync-catalog.mjs; never hand-edited)
    catalog-render.mjs    pure per-frame transition descriptors (push, zoom, iris, clock, blinds, blur, flip, dip overlays) + their audit
    overlays.jsx          generic React layers that apply a descriptor (LayerFx, DipOverlay)
    picture-mode.mjs      pictureMode(): what a shot shows on a frame; TYPE_TABLE (derived); tailWindow(); auditPictureLayers(); whipGeometry()
    validate.mjs          validateConfig(), collectWarnings(), validateSources(), the config schema checks
    caption.jsx icons.jsx transitions.jsx ending.jsx cards.jsx intro.jsx
  tools/sync-catalog.mjs  generate src/catalog.generated.mjs from the catalog; --check exits 1 on drift
  lib/stage.cjs           hash-verified staging of config.bindings -> `sources`
  lib/jsx-loader-no-child.cjs   optional in-process JSX loader (--jsx-loader no-child)
  episodes/ep04/          the first episode's adapters + parity runner (the ONLY place with episode numbers)
  tests/                  node --test "tests/*.test.mjs" (+ tests/fixtures/engine-events.json)
```

## Run

```
node render.cjs --config kit-config.json --mode review --out cut.mp4 [--overwrite]
node render.cjs --config C --stills "name:frame,name:frame" --outdir D          # PNG stills
node render.cjs --config C --still 123 --out frame.png
node render.cjs --config C --range A-B --out clip.mp4                           # partial render (never the film)
node render.cjs --config C --range A-B --png-seq DIR                            # lossless element-<frame>.png
node render.cjs --config C --mode master --out master.mp4 --overwrite           # scale 2, no label
node render.cjs --config C --check-only                                         # validate + bundle + select, render nothing
```

Options: `--mode review|master` (default review; review = scale 1 and the on-screen label `config.review.label`, master = scale 2 and
**no label**, a label is refused), `--scale N` (integer, default by mode), `--comp Film|EndLogo`, `--concurrency 1|2` (3+ is refused),
`--preview` (accept preview-only sources: stills / `--range` only, in EVERY mode; a `--range` covering every frame counts as a full render and is refused; such stills and ranges carry a red "PREVIEW SOURCES - NOT MASTER" mark; `--no-preview-mark` no longer exists), `--reproduction-only DIR` (parity / reproduction runs: every output must lie inside DIR, the record is stamped `reproduction_only`, reproduction-only waivers are accepted, and with `--drop-preview-mark` (stills only) the PREVIEW mark is omitted; nothing else may drop it), `--stage-needed` (stills / ranges: stage only
the video clips those frames need, so a 4K still does not copy every clip), `--browser PATH` (else `REMOTION_BROWSER`; the kit does not
search any episode folder for a browser and never downloads one: an episode runner passes the cached headless shell), `--workdir DIR`, `--jsx-loader no-child`.

Remotion packages resolve from `<workspace>/jenniejoy-zoo-film/node_modules` (override: `REMOTION_PACKAGES`). The bundle, the staged
public dir and the browser cache logic are those of the per-episode review/master renderers it replaces. Every render writes a record JSON next to the
output (`--still N --out`, `--range ... --out`, full film; `--stills` writes `_stills-record.json`): config sha, compositor sha, staged input hashes, timings, `gpu_used_deliberately:false`.

Tests: `node --test "tests/*.test.mjs"` (literal grep, validation, per-frame audit, label rule, adapter).

## Composition props

`Film({config, scale = 1, label = null, previewMark = null, sources, partial = false})`

| prop | meaning |
|---|---|
| `config` | the kit config (below). Validated on mount: a bad config throws before the first frame. |
| `scale` | integer. The design canvas is 1920x1080; the composition is `1920*scale` x `1080*scale` and the whole canvas is scaled, so captions, cards and vectors render natively (review 1, 4K master 2). |
| `label` | string or null. Shown top-left on review cuts only. The master passes null (enforced by `render.cjs`). |
| `previewMark` | string or null. Shown top-right when the picture bindings include preview-only sources (set by `render.cjs`). |
| `sources` | staged file names (what `staticFile()` resolves): `{opening, logo, music, ambience, fonts:{regular,bold}, shots:{<id>:{audio, segments:{<segId>:file}}}, tails:{<transitionId>:file}, icons:{<iconKey>:file}, cards:[{icon, audio}]}`. `render.cjs` builds it from `config.bindings`. |
| `partial` | true when clips were staged lazily (`--stage-needed`): null clips are tolerated. |

`EndLogo({config, scale, sources})` is the standalone end card (same `EndPlate`, starts at the join state, then static).

## Kit config schema (`jjk-remotion-kit/config/v1`)

All frames are global frames at `fps` unless noted. Everything episode-specific is here; nothing is in `src/`.

| key | content |
|---|---|
| `schema`, `id`, `fps` | `"jjk-remotion-kit/config/v1"`, episode id, frames per second |
| `timeline` | `{introFrames, mainFrames, endCardFrames, outroStart, outroFrames}`. `introFrames + sum(shot frames) + outroFrames == mainFrames`; the file is `mainFrames + endCardFrames` long. |
| `review.label` | on-screen label of the review cut (G-LABEL: must equal the receipt `quality_label`) |
| `clock.shotTable` | optional master-clock guard `{<shotId>: [start, frames]}`; the config is refused if any shot differs |
| `strings` | `{cardsHeader, cardsHeaderClosing}` (outro header texts) |
| `intro` | `{kicker, titleLines[], pill, footer, mark: 'drop'|'none'}` |
| `shots[]` | `{id, start, frames, speechEndS, vi, captionLines: 1|2, words:[{w,startF,endF,keyword}], segments:[{id, from, frames}]}`. Shots are contiguous from `introFrames` to `outroStart`; segments are contiguous inside a shot. `words` must not be empty (no whole-line caption fallback). `captionLines` picks the caption-panel height the icon pop clears. |
| `transitions[]` | see below |
| `icons[]` | `{id, shot, icon, frame, totalFrames, holdFrames?, fadeFrames?}`; `icon` is a key into `sources.icons` |
| `ending` | see below |
| `cards[]` | `{term, ipa, vi, exampleEn, start, frames}`; `start` is relative to `timeline.outroStart` |
| `theme`, `motion` | optional overrides of the presets (below) |
| `bindings` | render-time only, never given to the compositor: `{opening, logo, music, ambience, fonts?, shots:{<id>:{audio, segments:{<segId>}}}, tails:{<tid>}, icons:{<key>}, cards:[{icon, audio}]}`, each `{path, sha256}`; optional `materialized:{path,sha256}` (stream-copy cache of a concat list) and `preview:true`. |

### Transitions

`{id, type, boundary, from, to, frames, direction, start, params?, continuity?, framing?, ...}`; `from` / `to` name a shot id or its last / first segment id.

**The preset catalog is the single source of truth.** `type` is a preset name from `<skill>/schemas/transition-presets.json` (the file the engine's
`engine/editorial/presets.py` loads). `tools/sync-catalog.mjs` generates `src/catalog.generated.mjs` from it (rules only; display text stays in the
JSON), `node tools/sync-catalog.mjs --check` exits 1 on drift (a node test runs it, so a hand-edited or stale copy fails `npm test`), and
`TYPE_TABLE` / `TRANSITION_TYPES` / `NEEDS_CONTINUITY` in `picture-mode.mjs` are DERIVED from it: **every READY preset name is a valid kit
`type`** (30 today), planned presets (`glitch`, `ripple`, `grid_dissolve`) are refused with the engine's wording. A new catalog entry needs no
kit validation edit; it needs a renderer only when its `renders_as` is new (a test fails otherwise). The catalog is never edited by hand in the
kit: change `gen_presets.py`'s output, regenerate, run `node tools/sync-catalog.mjs`.

`renders_as` picks the renderer branch, so aliases share one: `crossfade`/`dissolve` -> dissolve, `wipe_linear`/`wipe` -> wipe, `pan_motivated` ->
whip, `dip_white` / `dip_white_legacy` / `dip_black` / `light_leak` / `film_burn` -> the dip family. `type: dip_white` with 9 frames means
`dip_white_legacy` (the first build's schedule), exactly as in the engine; an explicit `preset` / `renders_as` on the row must agree with the
catalog.

Per-preset validation (all from the catalog entry, same wording as the engine where it has a message):
- `frames`: `fixed` | `min`..`max` | `even`; a dip row WITH its own `schedule` (historic builds) is judged by that schedule instead (frames == its length);
- `direction`: `required` means +1 / -1; presets that ignore it accept anything;
- `params`: unknown names refused; number / integer / boolean / enum with `min` / `max` / `values`; defaults fill the rest (`resolveParams`);
  the iris layout numbers live in `config.ending`, so `required` params are not enforced in the kit;
- `tail_frames`: `none` | `all` (the window) | `half` (`ceil(frames/2)`, card_flip_3d) | `schedule` (the `out_tail` rows): the ONE `tailWindow()`
  feeds the compositor, the staging probe, `tail.verifiedFrames` (a preset may not play more tail frames than were verified) and the audit; a
  preset whose `tail_frames` is not `none` needs a `tail`;
- `window`: `at_boundary` | `centred` | `from_boundary` | `schedule` | `iris`: `start` must be where the window mode puts it (and `end_exclusive`, when
  written);
- `continuity`: a `shows_both` preset between pictures needs `agree`; one-shot presets (dip family, `card_flip_3d`, `cut_push`) never overlap, whatever
  the continuity (the per-frame audit refuses an overlap);
- `safe_for`: a graphics-only preset (`card_slide`, `plate_in`) between two pictures, or a picture-only preset between two graphics, is refused;
- dip family: schedule from the row or the catalog default, exactly one pure frame, `out` only before the boundary, `out_tail` contiguous t = 0..n-1, the
  peak (and the sparkle burst, unless `params.sparkles` is false) before the first spoken word.

`collectWarnings(config)` (exported by `validate.mjs`) returns build warnings that are never refusals: `framing: 'same_framing'` between two pictures
with a visible transition (anything but `cut`, `cut_push`, `none`) and the legacy 9-frame dip. `render.cjs` may print them.

**Renderers (fixed-timeline overlay model, never a TransitionSeries; the master clock does not move).** `src/catalog-render.mjs` holds PURE per-frame
descriptors `descriptor(type, params, frames, direction, t)` -> `{out, in, overlay}` with layers `{visible, opacity, tx, ty, scale, rotX, rotY,
blurPx, brightness, clip}` (px of the 1920x1080 design canvas). `out` is applied to the outgoing native TAIL layer (`TailLayers`), `in` to the
incoming shot picture (`ShotPicture`) by the generic layers in `src/overlays.jsx` (`LayerFx`, `DipOverlay`). Progress is `u = t / (frames - 1)`:
the outgoing picture is whole on the first window frame, the incoming one on the last. `auditSeries()` proves it (and the one-shot / both-visible
property and monotonic coverage); `validateConfig` runs it on the descriptors of every transition, `auditPictureLayers` counts only the tail layers
a descriptor leaves on screen.

| family | presets | what the descriptor does |
|---|---|---|
| cut | `none`, `cut`, `cut_push` | nothing / nothing / the incoming picture settles from `scale_from` to 1 over `frames` (one picture, no tail) |
| push | `push_slide` | both pictures travel one canvas apart along `axis` (`direction` +1: out leaves left, in enters from the right), `ease` |
| zoom | `zoom_through`, `zoom_out` | out grows to `scale_out` and fades while in grows from `scale_in_from` (blur `blur_px`); `zoom_out`: out shrinks to `scale_to` ABOVE the incoming and fades at the end (mounted inside the shot picture so it never covers the captions) |
| iris | `iris_circle`, `iris_diamond` | in is revealed through a circle / diamond growing from (`centre_x`, `centre_y`) (soft edge `softness_px`) over the outgoing picture |
| wipe | `clock_wipe`, `blinds`, `wipe_linear` | clock: in revealed through the swept sector (polygon: centre, start ray point, passed corners, end ray point; from `start_angle_deg`, `clockwise`); blinds: `count` slats each opening by the same fraction (`axis` h / v); wipe_linear / `wipe` / `cloud` / `bubble` keep the masked-wipe renderer |
| dissolve | `crossfade`, `dissolve`, `blur_crossfade`, `focus_pull` | crossfade / dissolve: the existing dissolve layer (`curve`); blur_crossfade: out blurs up to `blur_px` while in sharpens and fades in; focus_pull: only out defocuses (and swells 5 %), in fades in sharp |
| dip | `dip_white`, `dip_white_legacy`, `dip_black`, `light_leak`, `film_burn` | the `schedule` (row or catalog) gives `white` per frame; `dipDescriptor` turns it into exposure, blur and an overlay: flat colour (white keeps `motion.dip.colour`; black dims), or seeded radial blobs (seed = boundary) over a base that is opaque on the pure frame |
| 3d | `card_flip_3d` | ONE face per frame: out rotates 0 -> 90 deg over the tail frames (`ceil(frames/2)`), then in rotates -90 -> 0; `axis` x / y, `perspective_px` |
| camera | `whip`, `pan_motivated` | the existing whip renderer (`outFrames` / `inFrames`) |

`npm test`: `catalog-sync` (generated file in sync, TYPE_TABLE derived, engine presets module == kit reading for every preset), `presets-validation` (every rule above
per preset), `descriptors` (endpoints, monotonic progress, one-shot / both-visible audits and that the audit bites, determinism, parameter
extremes, family geometry), `render-smoke` (three presets through `render.cjs --stills` when a browser is available).

#### Original type notes

The sections below are the rules the earlier rounds pinned; the catalog now generates the same table.
| type | shows both | tail only | extra fields | rule |
|---|---|---|---|---|
| `whip` | no | no | `direction` +1/-1, `outFrames`, `inFrames` (<= preset array length) | ONE full copy of the shot moves; the exposed side is filled by a strip of the shot's own edge columns, flipped and stretched ~24x horizontally (smeared edge pixels, not a recognisable second picture). The strip box comes from `whipGeometry()` and is the box `WhipTiles` renders. Coverage is checked for real: `whipCoverage()` computes, in the moved layer's coordinates (scale about the canvas centre, then translate), where the strip lands for every offset / zoom the schedule draws (`whipSteps()`) and the strip must reach the canvas border; validation refuses a config whose `motion.whip.extenderWidth` is too small and `WhipTiles` throws instead of drawing an uncovered strip. Whip frames must be even. |
| `dip_white` | no | no | `boundary`, `schedule: [{t, shot, white}]` with shot = out / out_tail / in / none, `tail: {startFrom}` | exactly one white-peak frame; at most ONE shot per frame. `out` only before the boundary (t < 0), `out_tail` and `in` only from it (t >= 0). `out_tail` needs a `tail` and its rows must be exactly t = 0..n-1 (no gap): the tail plays on frames boundary .. boundary+n-1. The incoming shot is not rendered while the tail / white peak shows. |
| `bloom` | no | no | `start`, `frames` | warm bloom bridge |
| `iris` | no | no | uses `ending` | iris on the outgoing shot, logo disc grows out of the closing circle |
| `dissolve`, `cloud`, `bubble`, `wipe` | **yes** | **yes** | `frames`, `seed`, `direction` (+1/-1 for cloud and wipe), `centre` (bubble), **`tail`** | two shots in one frame: needs `continuity: 'agree'` (placements proven identical, e.g. by `comfyui-blender` scene_layout continuity) AND an outgoing `tail` (the outgoing shot keeps playing under it; continuity does not replace the tail). `wipe` is the cloud mask without bumps (straight soft edge). Otherwise use whip / dip_white / bloom / cut. |
| `card_slide`, `plate_in` | **yes** | no | `direction` +1/-1 (card_slide) | informational (cards and the plate drive their own timing). Shows both sides, so with a picture shot on either side they need `continuity: 'agree'`; between two graphics (cards, plate) they are allowed. |
| `none` | no | no | - | carry |

Rule for every showing-both type (engine rule): `continuity: 'agree'` is required whenever a PICTURE SHOT is on either side. A picture
side is any shot id or any segment id (first, last or middle) of a shot; only between two graphics (cards, plate, intro / outro) is it allowed
without.

Anchoring (refused otherwise): every drawn transition has an integer `start`; `boundary` equals the incoming shot / segment start and,
for whip / dip_white / iris AND the tail-only types, the outgoing shot / segment END (the `from` must be a real shot or last segment);
tail-only types have `start === boundary` and `start ===` the incoming shot start, so the tail and the picture mask cannot drift apart.
Each EDGE segment has at most ONE incoming and ONE outgoing transition (a shot id counts as its first segment for entering and its last
for leaving; an indexed lookup would let the last one win silently). Every `from` / `to` of every transition names a real shot / segment
or a graphic (`INTRO`, `OUTRO`, `END_PLATE`, `ENDLOGO`, `CARD_<term>` of an existing card); a typo would otherwise attach to nothing.

Engine row rules mirrored: whip and bloom frame counts are even, `dip_white` frames equal its schedule length, `none` has 0 frames and
every other type more than 0, `card_slide` / `cloud` / `wipe` need direction +1/-1.

Dip peak position (jenniejoy-remotion rule, G-CUT). Let `peak` be the frame `boundary + t` of the `white: 1` row and `first` the
incoming shot's first SPOKEN frame, taken from the onset evidence when the config carries it (`shot.speechOnsetF`, the first sustained
/ voiced onset measured on the bound WAV, e.g. word-timing `onset_fix.new_start_frame`; the caption start can sit on the unvoiced
pre-roll of the WAV, which is noise, not speech) and from the caption start otherwise. Every message and the rule report say which basis was
used ("onset evidence" / "caption-based"):
- `peak >= first` is refused (`dip_peak_before_first_word`): the white peak hides spoken frames;
- `peak + reach >= first` is refused (`dip_sparkle_before_first_word`) where `reach = motion.dip.peakSpan` while `motion.dip.sparkles > 0`
  (0 without sparkles): the seeded sparkle burst is drawn peak +- peakSpan frames and would overlay the first spoken frame.

Waivers: only a historical config may pass these two rules, through `config.waivers`. Two forms:
- approved: `{rule, transition, reason, approved_by, approved_at (a real calendar date, YYYY-MM-DD, optional time), review_render_sha256 (64 hex)}`;
- reproduction-only: `{rule, transition, reason, reproduction_only: true, review_render_sha256}` with NO approval fields (it is not an approval);
  a render using one must pass `--reproduction-only DIR` (outputs inside DIR).
A waiver without all required fields does not waive; a waiver that is not needed (its transition does not violate the rule) is itself an
issue; every used waiver is printed (`WAIVED ...`) and copied into the render record. The adapters create waivers only from an explicit
option (`--waive-historical-dip` with `--waiver-approved-by` + `--waiver-approved-at`, or `--waiver-reproduction-only`, plus
`--waiver-render FILE` or `--waiver-render-sha256`), never from a schema string, and never invent approval fields.

Tail files: `tail.startFrom` is a delivery-frame offset into the bound tail file and `tail.editorialFrames` (required) the native frames of
that file the editorial cut already uses (a tail core that starts at its first tail frame: 0); `tail.fileFrames` (required) is the frame count the config describes for the bound file, which must match the probe exactly (a full native clip where a short tail core is expected is refused); `tail.verifiedFrames` (required) is the number of output frames the engine's tail check covered and a transition may play at most that many tail frames (a dip with fewer `out_tail` rows is safe, with more is refused). The tail numbers (`startFrom`, `editorialFrames`, `fileFrames`, `verifiedFrames`) are NOT taken from an unverified config: the adapters read them from the build's events record (`events.transitions[id].outgoing_tail`: `start_from_frame`, `editorial_frames`, `native_frames`, `tail_output_frames`) and refuse a review or master config whose own copy differs by one frame, or a transition that has a tail in only one of the two files. The events record is a build artifact, not trusted engine output, and config + events can be edited consistently, so the build is bound to its receipt: `loadBuild()` (adapter) reads the config, the events file and the receipt once each and refuses unless the sha256 of the config and of the events file equal the ones in the build's `RECEIPT.json` (or, for an engine-built build, the hashes the real stdout of `jjv editorial build-config` nests under `outputs["review-config.json"]` / `outputs["events.json"]`) and the word timing is bound too: a build receipt must carry `word_timing.sha256` (a receipt without it is refused) equal to the config's; the engine summary has no word-timing key, so the word-timing document itself (path resolved against `episodeRoot`, required for a relative path) is hashed and compared with the config's `word_timing.sha256`. `adapt()` refuses a build that was not loaded that way (the token `loadBuild()` returns is frozen and registered in a module-private set: a hand-built or copied token is refused), records the receipt sha256 in `provenance.build_receipt`, and the provenance hashes are those of the verified bytes. The value depends on the build (3 for the earliest build's dip schedule, 1 for the later 8-row schedule), so it is compared with the events file, not with a constant. At staging, and in the master adapter CLI,
every bound tail file is probed (frame count, native fps) and the check is EXACTLY `engine/editorial/transitions.py` `check_tail`, for any
native / delivery fps pair: `available = frames - editorialFrames`, `need = ceil(4N/5)` (the engine's fixed `ceil(0.8 N)`),
`last = ceil((startFrom + N - 1) * nativeFps / fps)`; refused if `available < need` or `last > frames - 1`. A test runs the real engine
and the kit on a 33,120-case grid (nine fps pairs, independent editorial / delivery values, every native frame count 0..45 so the last used index is
bracketed on both sides) and asserts zero disagreements. The tail window
itself (`tailWindow()` in `src/picture-mode.mjs`) is the single definition used by the compositor, the per-frame audit and the staging step.

`pictureMode()` is the single decision function: the compositor draws what it returns and `auditPictureLayers()` replays it for every
frame of the film. A frame that mounts two shot pictures is accepted only if every tail on it belongs to a `continuity:'agree'`
transition. `Film` runs the audit at mount (via `validateConfig`), so a violation fails before any frame is rendered.

### Ending

Required when an `iris` transition exists: `irisStart, irisClosed, irisCentre[x,y], discIn, discSlideStart, discSlideEnd, discSlideX,
discFadeStart` (ordered), plus `pillLeftX` (measured left edge of the first vocab pill) whenever the disc is still on screen during
the first card. Rules enforced: `discSlideX + discR < pillLeftX` and `discSlideEnd <= first card start` (the disc never covers a vocab
word while it is spoken). Required with an end card or a plate: `plateStart, speechEndFrame, plateEn, plateVi` with
`plateStart >= speechEndFrame` and `timeline.endCardFrames > 0` (the plate belongs to the end card) (the plate never covers the last word while spoken) and `speechEndFrame` not before the last dialogue word's end or the last vocab word's start, and `tailFrom` (music tail start frame, the end
card is a separate tail of `endCardFrames` carrying only the logo plate and the music tail).
Optional per-episode overrides of the style defaults: `irisEndRadius, discCentre, discStartR, discR, discFadeFrames, ...`. The end-plate and disc layout numbers (logo size, text positions, fonts, springs, disc logo ratio) are presets in `motion.ending` / `motion.ending.plate`.

**Plate style** (`ending.plateStyle`, default `motion.ending.plate.style` = `v008`): the plate timing is data (`motion.ending.plate.styles`,
evaluated by the pure `plateFrame()` in `presets.mjs`). `v008` is the original plate (scrim 0 -> 1, springs). `v010` is the plate the approved v013
cut uses: scrim starts at 0.4, the logo is not drawn at all before plate clock 2, logo and pill ease out (cubic) over 8 frames, text fades 3-6 / 4-7.
An unknown style is refused. `adapter-engine.cjs` selects `v010` (episode text `ending.plateStyle` may name another). **EndLogo audio tail**
(`tailFadeIn`, `tailFadeStart`: gain 0 -> 1, hold, fade out to the last end-card frame) comes from episode text `ending.endLogoTail {fadeInFrames,
fadeStartFrames}`, because the build writes those fades only as prose; a missing key is refused.

### Segments: the ending as its own joined segment (T-E42 addendum, foundation of T-E45 P2)

A film is rendered as a list of **segments** that cover `[0, total)` exactly: `render.cjs --segments-plan` prints it (no browser). With an
iris ending the default plan is `main` (everything up to the first frame with no shot video, `discIn + 3`) and `ending` (logo disc, hold,
vocab cards, plate, EndLogo: vector + fonts + logo only, so it stages and decodes no shot video). A config can declare its own cut list in
`config.segments` (`[{id, kind, start, end_exclusive}]`: exact cover, unique ids, and no cut inside an iris / dip / both-pictures window).

```
node render.cjs --config C --segment ending --out ending.mp4        # SILENT, one codec set for every segment, record carries framemd5 + plan sha
node render.cjs --config C --audio-only --out mix.wav               # the whole-film audio once, 48 kHz (1600 samples per 30 fps frame)
node tools/join-segments.cjs --segments main.mp4,ending.mp4 --audio mix.wav --out film.mp4   # stream-copy join + <out>.join-record.json
```

The join refuses a segment that changed after its render, records of different plans, non-contiguous segments, differing stream
parameters, a film whose framemd5 column is not the concatenation of the segments' columns, non-continuous pts, a wrong frame count or an
audio mix that does not match the film length. Re-rendering the ending alone and re-joining reproduces the film byte for byte. See
`SKILL-SECTION-T-E42-kit-ending.md` for the decisions (who owns the iris, why the audio is not cut).

`cut_push` (the approved v013 push) runs its eased progress as `k / frames`: frame k of the window has scale `1 + (scale_from-1) * (1 - easeOut(k/frames))`,
so the window ends one eased step short of 1.00 and the plain incoming picture starts on the first frame AFTER the window (frames B..B+11 of a 12 f push, plain from B+12). Every other
descriptor preset runs 0..1 over its window (`k / (frames-1)`).

### Incremental build: segment cache and node keys (T-E45 P2)

`--segments-file segments.json` (the engine's `jjv/segments/v1`) becomes `config.segments` (refused when its `fps` / `total_frames` differ
from the config, and by the same cut rules as a declared list). `--segments-build CACHE --out film.mp4` then renders only what is stale:

```
node render.cjs --config C --segments-file segments.json --segments-build CACHE --explain             # table of node keys + RENDER / COMPLETE + why, renders nothing
node render.cjs --config C --segments-file segments.json --segments-build CACHE --out film.mp4        # renders the stale segments (child --segment runs), joins
     [--force-segment ID,ID]  [--build-concurrency 1|2]  [--mode master]
```

* **Node key** of a segment = sha256 of the Remotion version, the browser exe, fonts, codec set, mode / scale, the catalog, the hash of the
  video-relevant kit `src/**`, and the segment's **dependency slice** (`lib/segdeps.cjs`): the global leaves (schema, fps, timeline, theme,
  motion, clock, waivers, review label), its own range, the shots / transitions (effect window) / icon events / cards that intersect it, the
  intro / ending blocks it reaches, and the sha256 of exactly the picture / tail / icon / opening / logo files its frames mount (never paths).
* `CACHE/composite.segment/<key>/` holds `segment.mp4`, its render record and `record.json`; the same key is never rendered twice. A cached
  segment whose bytes no longer match its record is CORRUPT and the build **refuses** (no film); `--force-segment ID` re-renders it.
* The mix has its own key (`CACHE/audio.mix/<key>/`): stems, music policy, dialogue / card WAVs, the clips' own audio, all timing and the
  audio-only kit sources; a purely visual change (strings, theme, intro, plate text) leaves it alone, and an audio change renders no segment.
* `segments-run.json` (in CACHE and next to the film) lists every segment's status, its stale reason (the slice leaf that changed against the
  previous build, e.g. `shot:<id>.words.2.startF`), seconds spent and the estimated seconds saved by the cache.
* The slice is checked by a property test (`tests/round14-p2-property.test.mjs`): every config leaf outside a segment's slice is mutated and
  the segment's frames must stay byte-identical; a slice function that drops a part is killed by the same test.

### Motion presets

`DEFAULT_MOTION` in `src/presets.mjs` holds every timing / spring / layout preset: `spring`, `stagger`, `cards`, `intro`, `caption`
(caption), `icon` (incl. `capHeight:{1,2}`), `whip` (offset / blur / zoom arrays), `bloom`, `dip`, `wipe`, `ending` (+ `plate`), `label`, `previewMark`. A config overrides any
leaf with `config.motion = {caption: {fontEn: 46}, whip: {zoom: 1.06}}`; objects merge key by key, arrays and scalars are replaced; an
unknown key is a validation error (no silent no-op). `config.theme` overrides the palette the same way.

## How review and master use it

Same config, different bindings and deliverable:

| | review cut | 4K master |
|---|---|---|
| `render.cjs` | `--mode review` | `--mode master` |
| scale / size | 1 / 1920x1080 | 2 / 3840x2160 |
| label | `config.review.label` on screen (G-LABEL) | none (a label is refused) |
| picture bindings | upscaled editorial clips | hash-bound 4K sources, 4K tail cores; a FINAL source must carry a receipt binding `{kind, path, sha256, binds}`. Staging RE-READS the receipt content (`lib/receipts.cjs`, the same module the adapter uses): a shot receipt must be COMPLETED with the clip's path and sha256, a seam-blend receipt must have a known schema and `output.sha256` = the clip's, a tail receipt must be the tail map (exactly one row for the transition with the clip's sha256) or a COMPLETED receipt for the clip. A text file that merely names the hash, a changed receipt, or a relabelled preview is refused. A final source may not carry `materialized` (only previews are materialized): it stages exactly the attested file, and the staged bytes are re-hashed against the attested sha256 |
| crf | 18 | 16 |
| preview sources | refused unless `--preview` (stills / `--range` only) | refused unless `--preview` (stills / `--range` only); such stills get the PREVIEW mark |
| waivers | allowed (approval fields required), printed and recorded | refused in every master-mode render except stills (a master `--range`, covering the film or not, is refused too) |
| adapter gate | - | the master adapter refuses unless `master_ready === true` and `missing_shots` / `missing_tails` are empty (`--preview` is the explicit opt-in for stills) |

The master adapter checks that the master is the SAME film as the kit config: identical shot / segment / tail keys, identical shot
`start_frame` and `duration_frames`, segment `delivery_frames` and `relative_start_frame`, and transition `boundary` (a clock difference
is a refusal naming each mismatch). Every bound picture clip is probed for its frame count (staging probes the clips it stages; the
adapter CLI probes all of them for a real master config; `adaptMaster()` itself checks structure, clock and receipts only, the media probes run in that CLI and in staging): final sources must hold `ceil(frames * native fps / fps)` native frames, preview-only
sources (slates, concat previews) are reported in the record but not refused. The master adapter maps the 4K tail start frame from the master config for every tail transition (a 4K tail file is its own clip; the review start frame indexes the 24 fps native file) and must normalise the source kind (`segment.source_kind || segment.restored.source_kind`) into `binding.kind` /
`binding.preview`; `lib/stage.cjs` stages `binding.materialized` when a concat list was materialised into a preview cache and verifies
both hashes. Master-only readiness gates (every shot final, every 4K tail present) belong to the master adapter / builder, not to the kit.

## How an episode supplies its config

1. Build `kit-config.json` (any tool): timeline, shots with word timing, transitions, icons, ending, cards, strings, intro, bindings.
   The adapters in `episodes/ep04/` show the mapping from the first episode's review build (`adapt(reviewConfig, events)`; it
   accepts the engine-built `events.json` too, see `tests/fixtures/engine-events.json`) and the master variant that swaps in the 4K
   bindings and tail start frames. Anything the old build kept in constants (shot table, ending
   frames, pill position, which shot wraps to two caption lines) goes into the adapter or the config.
2. `node render.cjs --config kit-config.json --check-only` (validates, audits every frame, bundles, selects the composition).
3. Stills of the boundaries, `--range` clips, then the full film. Gates (G-CAP .. G-LABEL) and the independent critic still apply
   (see `jenniejoy-remotion` and `create-video-jenniejoykids`); the kit makes the structural ones fail early (continuity, one-shot
   dips, tail-only, vocab-word clearance, label).

## Parity

`python -I episodes/ep04/run_parity.py --work SCRATCH --report-dir SCRATCH_REPORT` (the report dir is required: use a scratch dir, copy a
report into the kit deliberately) renders the first episode through the kit and compares with (a) the ORIGINAL review compositor's
lossless PNGs and (b) the existing 4K master stills. The comparison is on decoded RGBA md5 (alpha included), pass = identical;
`all_pass` is computed from these reference-based rows only. The report also lists:
- **property checks** (kit-vs-kit, not parity, outside `all_pass`): the PREVIEW mark changes pixels only inside its box;
- the **rule report**: what the kit rules say about each review build adapted WITHOUT waivers (the earliest build: 3 late white peaks;
  the next two builds: 3 sparkle-reach issues each, the peak is one frame before the first word but the sparkle burst reaches it; the
  latest builds: none). The table has a column naming the evidence behind "first spoken frame" (word-timing onset evidence, or the
  caption start where a build's word timing has none) and a column "engine dip schedule": the later builds use an 8-row dip schedule with 1
  tail frame, which the engine (still encoding the 9-row / 3-tail-frame schedule, `transitions.py` `DIP_WHITE_SCHEDULE`) refuses; the report shows them as
  "engine-schedule mismatch (later design, BRIEF v009; not engine-verified)" so it stays visible (there is no approval artifact for that design, the films are not changed, the engine side is updated separately);
- **no-reference change detectors** (`master-regression.json`) for master frames that have no reference still: pinned md5, bound to the
  sha256 of the master config and tail files and to the pixel-hash method. Outside `all_pass`, not parity evidence, but loud: a missing pin
  file FAILS before anything is rendered unless `--pin` (create) or `--update-regression` (overwrite); a `stale` pin (sources changed,
  re-pin with `--update-regression`) exits non-zero unless `--allow-stale`; `CHANGED` (same sources, different pixels) always exits
  non-zero. The runner passes the historical waivers to the adapters with `--waiver-reproduction-only` (no approval fields) and runs every render with `--reproduction-only <work dir>` and the browser path it finds next to the episode's first review build.
The latest report is committed: `episodes/ep04/parity/PARITY.md` / `PARITY.json`. Comparison with an mp4 export is bounded by the codec (the original compositor's own lossless stills are
only 37-45 dB against its decoded mp4), so the lossless comparison is the pass criterion.
