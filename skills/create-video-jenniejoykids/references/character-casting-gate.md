# JennieJoyKids character-first production gate

For every new film, write the cast list and role descriptions while outlining the script. **Look up existing characters first; create only characters that have no usable canonical library entry.** This applies to every named human on screen, whether speaking or silent. Reuse the existing Alice and Mother identities and expressions in *Milk and Mom*; their presence in a new story is not a reason to render them again. A new Dutch dairy worker is a character, not a background detail; the first S02_A render turned her into a child because no adult character reference existed. Keep rejected frames and job receipts as evidence, never promote them to reference assets.

## 0. Existing-character reuse gate (before any GPU character job)

- Resolve each cast ID against `production-local/character-library/<id>/character.json` and its active `expressions_manifest`. For Mother the directory is `mother` and the character ID is `mom-alice`. Confirm that the canonical PNG and the expression PNGs needed by the scene exist and match their recorded SHA256 hashes. Read approval/review fields as recorded; a file's presence or a technical check does not silently upgrade its approval.
- *Milk and Mom* reuse entries: Alice `production-local/character-library/alice/2026-10-18-v1/canonical-approved-latest.png` (SHA256 `e87d4d0c372b315697d9dd948a91b12d5b0052838b12d9dff1808cc3ecb11b3a`) and Mother `production-local/character-library/mother/2026-10-18-v1/canonical-production-reference.png` (SHA256 `5f28f442b7d2253ec699b8cff7da0524ef78455cf3ca9b47847b7f050d7295f1`). Both active manifests select 12 expression PNGs. Mother is an existing production reference; her derived expression pack has not received separate user review. Keep that status visible.
- Write an episode cast-binding record with character ID, source version, canonical path/hash, selected expression IDs/path/hashes, wardrobe and review state. Stage or link the original assets into the new episode without modifying the shared library. Existing characters skip casting, face, turnaround and expression generation. Do not queue a second Alice/Mother character batch to make an episode-specific copy.
- If a required existing asset is absent, mismatched or unsuitable, mark that shot blocked and inspect the library/receipts and an accepted alternative. Do not silently re-render an existing character. A user-requested redesign is an explicit versioned exception, never a default reuse step.
- Render new storyboard compositions and video shots with the verified existing assets as ComfyUI reference inputs. Those new scene outputs are distinct from character-library generation; they still need visual identity and mouth-state QA.

## 1. Script and character prompts

Write the short story, role list, age/height relationships, wardrobe, scene actions and speech permissions. At this stage write **character creation prompts only for new cast entries** and rough shot directions for everyone. Existing Alice/Mother entries use the library's full descriptions and hashes in later shot prompts. Do not label prose or a generated file as an accepted character. Lock the selected local image engine and save an editable ComfyUI GUI/API workflow, model/ref hashes, seed, prompt ID and output hash for each new generation.

## 2. Canonical cast and expressions

For **each new named human character** without reusable library assets, including the silent milkmaid:

- Produce a full-body neutral casting image and a clear face/upper-body neutral image. Check adult/child age, head-to-body ratio, silhouette, height against the other characters, face, hair, skin, distinctive details, outfit and grounded feet. A request for an adult must not pass with a toddler-sized face/body.
- Produce front, three-quarter, side and back views in the same wardrobe. Derived views require pixel review and must not be claimed as source photos.
- Produce the same **12 expression IDs** used by Alice and Mom: `01-neutral`, `02-happy`, `03-sad`, `04-angry`, `05-surprised`, `06-afraid`, `07-laughing`, `08-crying`, `09-sleepy`, `10-sleeping`, `11-wink`, `12-thinking`. Every PNG has its own full prompt, parent canonical path/hash, image hash, expression description and review status. A character only needs expressions that its current scene uses to proceed, but the remaining IDs stay explicitly incomplete until rendered and reviewed; never claim a complete 12-pack from one portrait.
- Make scene-specific action/pose references before their first video use. For the milkmaid this includes a side-on stable stool pose, hands at Cow A's udder, a pail under the udder and a closed mouth. Check anatomy, prop contact and farm-side fence geography in the actual image.
- Record `characters/<id>/character.json`, `manifest.json`, selected canonical full-body/face assets, expression files, workflow copies, job IDs, hashes, and a per-asset `candidate | rejected | accepted` decision. Version replacements without overwriting history. Only accepted new-character asset hashes may be bound to a shot; this does not require regenerating an existing production character.
- For each finished ComfyUI image job, preserve the original GUI/API graph and receipt, then make a separate GUI review copy with `SaveImage` still present and a `LoadImage` preview node pinned to the exact output PNG copied into ComfyUI input by hash. The node title shows the real prompt ID and review state. Reopen the saved workflow from the film-named ComfyUI folder and verify that the image is visible; a `SaveImage` filename alone does not guarantee persistent preview after reopening. Mark rejected outputs visibly; never pin a different or imagined output to a prepared graph.

Animals that recur across scenes need their own consistent look/markings, count, relative scale and action references. They do not inherit the human 12-expression requirement unless the story gives them human-like acting.

## 3. Storyboard and complete scene prompts

Once the new visible cast for a shot has accepted canonical assets and the needed expressions/actions, and existing cast assets have passed the reuse/hash gate, write its **complete image and video prompts**. Alice/Mother reuse their verified production references and manifest-selected expressions at their recorded review scope; the scene itself still needs visual QA. Repeat the full visible-character descriptions, wardrobe, age/body scale, selected expression/action, role-specific mouth rule, environment, camera, props and continuity. Include reference paths **and hashes**; a name, a PNG path or “same as last scene” is insufficient. Use the verified character assets as actual image inputs in the local ComfyUI graph. Render and review every storyboard frame before H3. A background plate without the actors is only a background candidate, not a finished storyboard frame.

For each storyboard frame, check faces, age, pose, mouth state of silent listeners, foreground/background layering, contact shadows, hands/props, animal anatomy and frame-to-frame continuity. Record exact graph/seed/job/output hashes. Block a scene if any visible named character lacks an accepted identity anchor or required acting reference.

**Cinematic spatial QA:** define the camera axis and near, acting, barrier, background and far planes in the shot brief. For a pasture/enclosure scene, the front fence and visible side returns must read as one closed space; trace occlusion at every animal, person and rail overlap. Every cow's full body and hooves remain on the farm side, at a believable distance and scale. Reject extra animals, heads/legs through rails, floating actors, pasted-looking silhouettes, inconsistent foot shadows or a prop on the wrong side. Compare the rendered pixels with the blocking, because “behind the fence” in prompt text did not prevent the rejected S01_A v003 from showing three cows and ambiguous fence intersections. The episode-04 correction and five-plane check are in `production-local/JennieJoyKids-Story/04-milk-and-mom/concept/S01_A-CINEMATIC-BLOCKING-v004.md`.

Publish completed scene GUI review copies beside character copies under a film-named ComfyUI workflow folder with clear stage subfolders. Keep source graphs, output images and receipts in the film's versioned project tree; this UI copy is for inspection and must not silently replace the queued API graph.

## 4. Voice, motion and finish

Generate the exact final VoiceStudio WAV for each speaking turn and pronunciation; record profile/text/hash/duration and listen. Tie H3 lip animation to that WAV, then run the chosen SeedVR2 7B restoration only on accepted native motion. Remotion owns captions/icons/audio/master clock; HyperFrames supplies compatible graphics. Keep storyboard, native motion, upscaled picture and final Master as distinct states. A new voice, picture or timing revision invalidates dependent checks and requires a new version/receipt.

This gate is a **sequence and evidence rule**. It does not claim Alice/Mom rigs, the milkmaid 12-pack, all storyboard frames or any new film have already been completed. Inspect the episode tracker and real files before reporting readiness.
