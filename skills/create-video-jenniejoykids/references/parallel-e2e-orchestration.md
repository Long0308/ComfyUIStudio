# Parallel E2E film orchestration

**Last updated:** 2026-10-27. JennieJoy cartoon domain; NEWTECONS keeps its separate routing and permissions.

Use this reference when the request is to produce a full JennieJoy film or coordinate multiple engines/agents. The episode's `PLAN.md` is the canonical task board. Keep one row per deliverable with stable ID, owner/actual model route, dependencies, input hashes, output path/hash, exact job ID when a job exists, review verdict, next action and verification command. Show the same compact checklist in the chat at dispatch and update both at every boundary. A created folder, submitted job, agent report or green code test is not a finished scene. The Studio film/job view shows real media jobs and previews; `PLAN.md` remains the task tracker where the app has no task endpoint. Do not claim PLAN text is automatically synchronized to Studio.

## First five minutes of an episode or resumed session

Use the mandatory [event-to-owner engine dispatch table](engine-dispatch-contract.md). Music, SFX, subtitle, HyperFrames, Remotion and Studio publication are separately tracked lanes with named owners from startup; none may wait for the user to ask. Related tasks may share one child under the host limit, but their artifacts and acceptance stay separate.

1. Read `SESSION-HANDOVER-LATEST.md`, the film's `PLAN.md`, its cast bindings, script revision and last receipts. Inspect active child agents, Studio `GET /api/films`, VoiceStudio running/batch jobs, ComfyUI `/queue` and `/history`, output hashes and RTX 5080 occupancy. Reconcile unknown submissions before dispatch; a previous agent's report does not replace this readback.
2. Create or update film and shot IDs in the existing PLAN. Mark each lane `pending | in_progress | report_received | in_review | accepted | rejected | blocked` with a concrete owner and the smallest dependency. Preserve prior job IDs and rejected outputs. If Studio's film entry is absent, register the film before publishing media; registration is not a video job.
3. Dispatch all independent work **now**: shot script/prompts, missing character/Blender asset work, exact WAV/technical audio, bilingual caption design, SFX cues/stems, vocabulary art and HyperFrames elements. Assign one deliverable and a bounded file scope to each subagent. One agent may own several sequential tasks, but two agents must not write the same output path. Root handles integration, acceptance and the single GPU queue. If no specialist agent can be started, root owns the task and records the reason; do not leave an unowned lane waiting for a reminder.
4. Release ready shots independently. A scene can advance once its visible character anchors/required actions, spatial guide where needed, storyboard pixels and exact WAV are accepted. Later character expressions and unrelated scenes continue in parallel. Local ComfyUI image, H3 and SeedVR2 jobs are serialized against VoiceStudio/GPU encoding; native cloud images and CPU caption/SFX/Remotion preparation can overlap that queue. The first QA-accepted hybrid image can enter H3 without waiting for the alternate branch.
5. At every report, job completion, failure or user correction, verify the saved bytes/QA, update PLAN and Studio's **supported** film/job records, then dispatch the next newly unblocked task. Publish a truthful per-shot preview early. Preserve a versioned Master only after all bound AV, captions and mix have been checked at normal speed.

## Dispatch packet and shot card

Send one compact packet per task, not the whole session transcript. Required fields: `film_id`, stable `task_id`, `shot_id` or `global`, exact scope and owner/agent type, script/cast/voice revision, dependency paths with SHA256, allowed output directory, required artifact(s), acceptance checks, and GPU permission (`none` unless root explicitly assigns the queue). Ask for a return receipt containing `requested_model`, `observed_model` if verifiable, `output_path`, `output_sha256`, `prompt_id`/`job_id` if one actually ran, `verification`, `review_state` and `remaining_blocker`. Use `null` for a job that was only prepared. Agent names and saved workflow files are not inference receipts.

Each shot card records its line and language, speaker and silent listeners, final VoiceStudio WAV/profile/text/path/SHA/duration, cast image/expression/action paths and SHAs, spatial guide and camera, prop/fence/occlusion constraints, complete image and video prompts, target frame count/FPS, subtitle terms/timing source, SFX cues, expected carry from the preceding accepted clip and current status. The storyboard worker may prepare prompts before final WAV; H3 and final caption/lip timing wait for that exact WAV. If a speaker changes, invalidate that shot's lip/caption/mix dependencies, not independent character or icon assets.

For every adjacent pair, add `previous_shot_id`, `transition_type` (`continuous` or a named motivated cut), `shared_cast`, prior exit and next entry screen positions/poses/eyelines/prop states, camera axis, mouth owner, and `carry_in` path/frame index/PTS/SHA once it exists. The rule crosses scene labels: if two people remain on screen in scene 1 and scene 2 in the same space/time, the scene number alone never resets either actor. Default to exact last-USED-PNG → next frame 0 for a continuous pair; a camera cut may use the end image as a reference while the new first image changes viewpoint. Compare decoded boundary frames and a normal-speed seam before accepting either transition. Do not fill `carry_in` with a guessed hash before video exists.

Return-state rule: `prepared` means saved script/graph/cue with no inference output; `queued` needs a real prompt ID; `rendered_candidate` needs a real file and hash; `accepted_shot` needs visual/audio review of that hash; `master_rendered` needs an encoded file; `master_reviewed` needs full AV review. Update PLAN's `report_received` when a child responds, then perform independent root checks before `accepted`. Interrupt a finished child after consuming its report.

## Start the lanes together

After a brief identifies film ID, script, duration, cast and scene IDs, dispatch independent bounded work. Agent concurrency is for research, writing, CPU editing and asset preparation; heavy inference on the single RTX 5080 is scheduled serially. Check live service state, queue, GPU owner, old receipts and output hashes before scheduling the next CUDA job. Reuse a completed result by exact hash, and reconcile an unknown submission from queue/history before retrying.

For authorized JennieJoy images, use the [parallel hybrid contract](../../comfyui-video-pipeline/references/hybrid-image-routing.md): A is native cloud imagegen or an optional verified partner image node; B is an independent local ComfyUI route. Dispatch cloud/CPU and local work together where feasible while root retains one heavy CUDA owner. Two prompts in one ComfyUI queue are sequential unless real timing proves otherwise. An existing accepted A goes directly to its next consumer by hash; do not rerender it to create a race or wait for B's review. Native outputs enter the real H3 graph through `LoadImage`, with external tool provenance. Installed partner nodes do not prove verified auth/billing or a partner run.

## Per-shot release, not one whole-film barrier

1. Inventory existing characters first. Existing Alice/Mother identities and expressions are reused by hash. A user-selected candidate can become the visual identity anchor when explicitly chosen; record that decision and keep earlier rejects as history. Only a new character requires new casting. The entire expression library may be prepared in parallel; **the current shot needs only its visible characters and specific acting assets**.
2. Create a shot card with scene ID, script revision, spoken line, exact final WAV path/hash, visible people and reference hashes, who may move lips, camera/depth/prop constraints, image/video prompt, target duration and output version. A silent visible actor still needs identity and closed-mouth instruction, but no fabricated TTS profile.
3. Create/review its storyboard through the authorized parallel hybrid image routes, or reuse the accepted image already bound to that shot. When fence geometry, contact or occlusion matters, first save a Blender camera guide, then bind that real image/pass with the cast references to each route. Keep branch-specific prompts, input/output hashes, actual model evidence and local API/GUI workflows/prompt IDs when one ran. Import native cloud PNGs using real `LoadImage` and preserve their external tool receipt; no fake cloud node or invented local prompt ID. Reject an incorrect cow count, fence, mouth or pose from **pixels**, even when the prompt or guide was correct.
4. As soon as one shot has a reviewed anchor and final WAV, release its H3 work while later shots remain with the storyboard lane. Verify the speaking mouth and silent listener/milkmaid against that WAV; then restore/upscale that accepted clip. Run one bounded 2K/4K SeedVR2 pilot before a full episode when memory behavior is unknown. ComfyUI queue/VRAM remains single-owner despite parallel agents.
5. Remotion can prebuild caption/icon/flashcard components and SFX cues before scene clips finish. HyperFrames can build independent intro, transition or comparison graphics from hash-bound assets. They are components until bound into the Remotion Master clock. Export preview per accepted shot or an honestly labelled animatic; do not call it a full motion film. Render new 2K/4K Master versions after all dependent clips and stems pass their gates.

## Studio view and recovery contract

- The Studio film record exists at project start. After each actual image/H3/SeedVR2/finishing job, publish the output preview and `film_id`, real prompt/job ID, workflow path, source/output SHA and review status. Do not display a prepared workflow as a completed image or an image job as a video job.
- Use statuses `prepared`, `queued`, `rendered_candidate`, `rejected`, `accepted_shot`, `master_rendered` and `master_reviewed`. Only the latter two describe a saved film output, and only `master_reviewed` supports quality acceptance. Keep the user-facing board current even when another lane is still running.
- On interruption, read PLAN, job receipts, `/queue`, `/history` and files before starting anything. Preserve immutable old outputs; make a new version for a changed prompt, voice, expression, geometry or graphic. Invalidate only dependent stages: voice change affects lip/captions/mix; caption/SFX change affects compositor/mix; identity/shot-anchor change affects that scene's video and downstream carry; an icon change affects its graphics/render part.
- If one lane fails, continue independent lanes. Report the precise critical-path blocker and the next runnable task. Avoid guessed completion times until one representative job has measured duration and QA outcome.

## Domain and critical-path controls

The episode manifest/request selects `jenniejoy_cartoon_3d`; NEWTECONS selects `newtecons_live_action` in its own skill. Do not migrate corporate face/wardrobe templates into cartoon scene production without extracting and independently validating a generic module. Reuse the prior film's engine/character/voice contracts, not its footage or complete storyboard.

For a continuous sequence, prepare the full shot plan in parallel but prioritize ONE complete initial anchor. Its accepted H3 last USED frame supplies the next shot; do not demand twelve separately generated stills before the first video. A motivated camera/time cut gets its own anchor and continuity contract. Track guide acceptance, complete-frame acceptance and moving-shot acceptance separately.

Two consecutive local pilots/errors with the same defect trigger an independent graph/model/LoRA/mask/source-binding/queued-prompt inspection before another local inference, plus already authorized GPT image support. Record the two failures and reviewer findings; do not loop retries or add a new approval pause for the existing native cloud authorization. A subagent report outside its assigned scope is not accepted; check actual paths/hashes and reassign the task with a small context packet. Separate preparation/wait/render/review durations in the tracker. CPU/cloud and editorial work keep progressing while the GPU owner repairs a blocked local image route.
