# Picking and adapting prompts from awesome-opus5-5-videos

Repo: [yihui-dev/awesome-opus5-5-videos](https://github.com/yihui-dev/awesome-opus5-5-videos). Fetched 2026-10-27 (README, `LICENSE`, `data/videos.json`, and the prompt files cited below, all from branch `main`). Back to [SKILL.md](../SKILL.md).

## What the repo is (only what was fetched)

- A curated list of prompts for videos made with Claude Opus 5.5, where the model writes the animation as code (the README names HTML, Canvas, SVG, Three.js and similar; tags in `videos.json` include `canvas`, `svg`, `gsap`, `threejs`, `shader`, `css`, `physics`).
- **703 entries.** `prompts/` has one Markdown file per entry (the prompt, or in some files only a partial prompt or the creator's post text); `data/videos.json` holds the same entries as machine-readable metadata. Entry fields: `slug`, `author`, `author_url`, `post_url`, `category`, `tech_tags`, `prompt`, `prompt_partial`, `poster_url`, `skillry_url`, `added`, `has_remake`.
- Categories in `videos.json`: `motion` 369, `3d` 117, `explainer` 116, `interactive` 101. (The README's headline sections show smaller highlighted subsets; use the JSON counts for the full list.)
- Prompt file URL pattern: `https://github.com/yihui-dev/awesome-opus5-5-videos/blob/main/prompts/<slug>.md`.
- **No kids-education prompt found.** A keyword scan of all 703 prompts (kid/children/flashcard/vocabulary/alphabet/nursery/cartoon/mascot/preschool/toddler/phonics) returned no educational vocabulary or flashcard prompt. Everything here is generic motion craft (cards, timelines, kinetic text, UI morphs, explainers); adapt the craft, not the subject.

## License and attribution

- The repo ships an **MIT `LICENSE`** (copyright 2026 yihui-dev). That license covers the repository's own files. The README's credits say every video and prompt belongs to its creator and links each to the original post; it also says creators can ask for removal. Treat each prompt and video as **creator-owned**.
- Rules for us: **link, do not copy.** Quote at most a few lines when needed to explain an adaptation; never paste a whole prompt body into a skill, brief or commit. Keep the creator handle and post link beside any idea we adopt. Do not reuse third-party IP that appears in a prompt (e.g. a game franchise's characters).
- Prompts are starting points written for product launches and demos. Our briefs must rewrite them against JennieJoy/NEWTECONS tokens and the [brief template](brief-template.md).

## How to pick and adapt (checklist)

1. Start from our need (flashcard, title card, overlay), find the repo category above, then read **only 2 or 3 prompt files** (not the whole list).
2. Extract the craft in your own words: event order, timing style, banned list, verification step. Do not paste the body.
3. Rewrite against the brief: fps `30` (JennieJoy) or the NEWTECONS manifest clock, our tokens, bilingual copy, longest-string check.
4. Replace adjectives with numbers (hex, px, frames, damping).
5. Strip anything we do not want: third-party IP, cloud image generation, auto-generated music with unclear license.
6. Record the source in the brief as `inspired_by: <slug> (<handle>, <post link>)`.
7. Refresh the repo only when needed: the list grows over time (its README says new prompts were added on 2026-10-12), so counts above are as of this fetch.
