## Explicit subskill contract

- **Input Trigger:** QA-accepted complete storyboard anchor image (Branch A native GPT imagegen or Branch B local ComfyUI) + the exact receipt dialogue WAV, i.e. the WAV named in the H3 preparation receipt (`preparation.json` → `wav.sha256`; S01_A: `hybrid-v001/job.json` → `wav_sha256`) (48kHz stereo PCM16; trimmed once before H3 if trimmed).
- **Responsible Owner:** The live root/agent ID recorded in the film PLAN, using the local ComfyUI route on port 8188 running on RTX 5080. The skill name is not an agent ID.
- **Concrete Output:** Native 24fps H3 motion video clips (864×480), accompanied by exact last USED native frame carry PNG, prompt ID, GPU execution telemetry, and verified SHA256 hashes.
- **Downstream Result Consumers:**
  1. *SeedVR2 Restoration Lane:* Receives native clips for mandatory 4K restoration after a measured target-resolution pilot; the 2K 2560×1440 film = lanczos downscale of the finished 4K Master (downscale: PLAN T-V10; lanczos: `editorial/master-4k-v001/DOWNSCALE-2K.md`); no separate 2K SeedVR2 run.
  2. *Remotion Compositor (`jenniejoy-remotion`):* Receives native clips and carry frames for delivery timeline assembly (mapping native 24fps to delivery 30fps).
  3. *Studio Publisher (`jenniejoy-studio-webapp`):* Receives genuine prompt ID, output path, hash, and preview link for registration in `/api/films`.

## Single upstream audio trim & native frame carry

- **Single Audio Trim Rule (Case 06):** Each shot has exactly one dialogue WAV: the WAV named in that shot's H3 preparation receipt (`technical/motion-v00N/<SHOT>/preparation.json` → `wav.sha256`; S01_A: `technical/hybrid-v001/job.json` → `wav_sha256`), whose SHA256 the H3 job receipt must record identically (the receipt WAV). H3 conditioning and the Remotion mix use that same file and start offset. If silence is trimmed, trim **ONCE upstream before H3** so the receipt records the trimmed file; a trim made after H3 is a different file and must never replace the receipt WAV (episode04 S01_A: untrimmed `5d33ad49…`, see `technical/audio-binding-r27/S01_A-WAV-BINDING-DECISION.json`). Unpaired finishing trims create a confirmed integration risk; no affected final export has yet been observed. Do not trim audio independently in Remotion without a paired video offset, and keep full AV acceptance open until the actual export is reviewed. A shot with no speech conditioning (`native_speech_conditioning:false`, voiceover/nonverbal) has no receipt WAV; its editorial voiceover WAV must be named and hash-bound in the editorial manifest instead.
- **Frame Rate Mapping:** H3 native clips are generated at 24fps (e.g., 120 used frames = 5.0s). Remotion maps these to the 30fps delivery timeline (150 frames = 5.0s).
- **Exact Last USED Frame Carry:** Each shot pair must declare `continuous carry` or `motivated cut` in its plan. Only a declared continuous carry uses the exact last USED native frame (e.g., frame 119 for 120 used frames at 24fps) as frame 0 of the next shot; a motivated cut uses a newly approved anchor. Example: episode04 S01_B frame 119 is **not** a carry into S02_A (`create-video-jenniejoykids/error-db/h3-v003-spatial-restaging-and-carry-semantics.json`).

Updating ComfyUI pipeline configurations and skills establishes verified execution and error-prevention procedures; it is not model-weight retraining. ## ComfyUI MCP and Claude-node policy (R27 audit)

Evidence: `production-local/JennieJoyKids-Story/04-milk-and-mom/technical/pipeline-dataflow-v001/DATAFLOW-AUDIT.md`.
- **ComfyUI runs in Docker** (`Comfyui-Studio`, argv `main.py --listen 0.0.0.0 --port 8188 --disable-auto-launch --cache-none --reserve-vram 2 --enable-assets --disable-partner-nodes --disable-all-custom-nodes --whitelist-custom-nodes comfyui-krea2edit newtecons_live_preview newtecons_branding`). - **MCP tools safe against it:** `server_info`, `system_stats`, `validate_workflow`, `job`, `discover`, `auth_status`; the MCP already resolves to `127.0.0.1:8188`. Do **not** set `COMFYUI_URL`/`COMFYUI_HOST` (switches to remote semantics). Submit long jobs with `run_workflow(wait=False)` then `job(action="wait")`; the default wait is shorter than real H3/SeedVR2 jobs. MCP submission does not replace the shared `.comfyui-image-submit.lock`, queue/history check or receipt.
- **MCP tools forbidden here:** `launch_comfyui`, `stop_comfyui`, `restart_comfyui`, `update_comfyui`, `switch_comfyui_version` (they manage a host comfy-cli process with different flags → second CUDA owner); `install_node`/`workflow_deps` cannot work (no Manager, read-only mount).
- **Claude/Opus node:** the built-in `ClaudeNode` (`comfy_api_nodes/nodes_anthropic.py`, Opus 5.5 listed) is a cloud partner call via `/proxy/anthropic/v1/messages`: it uploads inputs, its text is non-deterministic, and it breaks hash-bound graphs. **Never place it in a render graph.** Claude orchestrates from outside through the MCP. A render graph must pass `validate_workflow` with no partner nodes. Since 2026-10-27 (T-E10, user decision) `production-local/comfyui-docker/compose.yaml` launches with `--disable-partner-nodes`: live argv contains it, `GET /object_info/ClaudeNode` returns `{}`, and the H3 S06_B3 (20 classes) and SeedVR2 pilot (15 classes) graphs are fully registered. The previous compose is preserved at `production-local/comfyui-docker/runtime-receipts/compose-before-r27-20261027090357.yaml`.
- **Dataflow optimisations** (trim/crop before post-process, several chunks per prompt, `SaveLatent` checkpoint, lossless H3 hand-off) are ranked in the audit; each one changes the graph and must be proven bit-identical or re-piloted before production. Production plan v004 deliberately stays a byte-faithful clone of the qualified v003 graph.
- **Guarded submit helper (T-E09):** any agent submits with `python .agents/skills/comfyui-video-pipeline/scripts/comfy_guarded_submit.py` instead of raw `run_workflow`/`POST /prompt`: `check` (container, queue, VRAM; read-only) -> `submit --graph <api.json> --receipt-dir <dir> [--expect-sha <sha256>]` -> `wait --receipt-dir <dir>` (writes `job.json` with output SHA256) -> `reconcile --receipt-dir <dir>` (read-only, by `client_id`; never POSTs).
  `submit` refuses on sha mismatch, partner/API or unknown node classes (unless `--partner-ok` with explicit spend consent), a held lock, a busy queue, or a reused receipt dir; it writes `dispatch-intent.json` before the POST and `submitted.json` after.
  It uses the SAME sentinel as the episode executors, `04-milk-and-mom/technical/.comfyui-image-submit.lock`, and holds it until the prompt leaves `/queue`. Monitor afterwards with MCP `job`/`system_stats`; never resubmit after an uncertain result, run `reconcile`.

## Production lessons written at handoff (R27, 2026-10-27)

- **ComfyUI crash mid-run (2026-10-27).** A sporadic `CUDA error: an illegal instruction` in SeedVR2 `lab_color_transfer` aborted ComfyUI; Docker restarted it (restart path now proven) but the executor waited forever on the lost prompt. Recovery: confirm container StartedAt > dispatch time, prompt absent from /history and /queue, no partial outputs → archive the chunk state with INCIDENT.json → ONE executor with `--resume`. Never run two executors; check the old PID is gone and the log folder exists. Engine fix T-E30 (lost-prompt classification, bounded auto re-dispatch, stall watchdog, single-executor guard). Error-db `comfyui-cuda-illegal-instruction-lost-prompt-executor-hang`.
- **Config edits invalidate pending plans.** Engine plans bind the whole resolved domain + machine sha; any edit to domains/*.json, machine.json, recipes or episode configs refuses every unexecuted plan. Before applying such an edit, list pending plans and re-run their execute dry-run; while a GPU run is pending, stage config changes until after it (error-db `domain-edit-invalidated-tail-plan-v3`).
- **Restoration scope = final editorial event list.** A 4K plan must cover every frame the review/master timeline reads, including tail handles borrowed by tail-only transitions, not just the editorial clips (ep04 plan v004 restored 1656 editorial frames and missed the S03_B/S04_B/S05_B tails; error-db `seedvr2-plan-editorial-only-no-tail-handles`).
- **ffmpeg colour tags go on the rawvideo input.** With ffmpeg 9, `-colorspace/-color_*` given only as output options convert the pixels (~3 Y levels, 37 dB) instead of tagging them. Pixel-identity checks use decoded `framemd5`, never psnr/ssim across files with different tags (the psnr filter converts too). Error-db `ffmpeg-output-colour-tags-convert-pixels`.
- **Frozen files during a run.** Run `jjv frozen verify` before briefing a builder; files in `FROZEN-EP04.json` are forbidden in the brief and changed only as staged copy + diff after the run (error-db `brief-targeted-frozen-file-during-run`).
- **Sandboxed codex subagents never render.** Gemini/DeepSeek via `codex exec` cannot launch Chromium/ffmpeg children (spawn EPERM, mojo 0x5); they prepare configs/scripts, root or a host-shell Claude agent renders (error-db `codex-sandbox-blocks-chromium-remotion-render`).
- **Memory container on the home machine.** Hindsight's extraction LLM is OpenCode Go DeepSeek V4.1 Flash via local New-API (`HINDSIGHT_LLM_MODEL=deepseek-v4.1-flash`, `token-newapi:3000`). Re-create it only with `production-local/engine/hindsight-loopback.override.yml` (the mirrored .env binds BIM02's Tailscale IP), then verify /health, env, bank stats and a 1-fact retain (error-db `hindsight-container-drift-stale-compose-and-bim02-bind`).
- **Memory retains are asynchronous.** Hindsight `202` is only queued; check `operations?status=failed` within minutes (ep04: 82/82 failed on DeepSeek 402; error-db `hindsight-retain-402-deepseek-insufficient-balance`).

## External asset pipeline & Quark Netdisk (夸克网盘) integration

- **Auth & Session Persistence:** Quark credentials (`QUARK_COOKIE`, `QUARK_NICKNAME`) are stored in `production-local/ComfyUI/.env` and mirrored in `config/user_info.json`.
- **Telegram Bot Automation:** In `@LPHome_A1_2026_bot`, sending `/quark_qr` or `/quark_login` generates a live QR code directly into the chat; scanning via the Quark mobile app triggers an automatic callback that updates `.env` without manual cookie extraction.
- **Virtual Drive Mounting (1TB Cloud Mount):**
  1. *Quark PC Client (官方电脑版):* Installing from Microsoft Store or `https://pan.quark.cn` mounts an explorer virtual drive (`夸克网盘`) in "This PC". All 4K video assets stream directly via Windows media players without taking physical storage.
  2. *CloudDrive2 / AList (WebDAV):* Mounts the 1TB Quark drive to a designated drive letter (`Q:\` hoặc `Z:\`).
  3. *Local Dynamic VHDX:* Can create a 1TB dynamic VHDX on drive `L:\` (2.1TB free) that expands only as files are downloaded.
- **Download Guard:** The Quark web/third-party API enforces a 100MB single-file limit (`code: 23018, download file size limit`) for standard accounts. Files > 100MB should be accessed via the Quark Virtual Drive or downloaded via the official desktop client.
